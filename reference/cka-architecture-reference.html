Cheat Sheet / Reference

Kubernetes 核心架構與組件功能速查 (CKA 必備)

呢份係你平時溫書同做 Lab 必備嘅速查表，將 Control Plane 同 Worker Node 各大組件職責、通訊路徑同故障特徵濃縮晒喺度。

1. 組件速查表

組件名稱 身處位置 生活化比喻 (香港職場版) 核心職責 (CKA 核心) 死咗會點？ (故障特徵)
kube-apiserver Control Plane 前台接待處兼總秘書長 全 Cluster 唯一暴露 REST API、認證/授權/準入控制、直通 etcd 嘅組件 全部 kubectl 玩完、整個 cluster 癱瘓无法接收新指令
etcd Control Plane 全公司唯一最高機密賬本 分散式 key-value storage，儲存 cluster 所有狀態與 manifest 集群失憶、所有組件無法讀寫最新狀態（高危災難）
kube-scheduler Control Plane HR 排更主任 過濾 (Filter) 及打分 (Score)，決定 Pod 分配去邊粒 Worker Node Pod 永遠卡喺 Pending 狀態
kube-controller-manager Control Plane 各部門巡邏監察隊 運行 Node, Deployment, ReplicaSet 等 controllers，確保實際狀態 = 期望狀態 Pod 死咗唔識自癒重啟、副本數量對唔齊
kubelet Worker Node 地盤包頭（Node 工頭） 同容器運行時 (CRI) 溝通、管理 Pod 生命週期、定時向上回報 Node 狀態 Node 變 NotReady、Pod 無法啟動或停止
kube-proxy Worker Node 交通交警（網絡轉發） 維護節點網絡規則 (iptables/IPVS)，實現 Service IP 負載均衡與流量轉發 ClusterIP 唔通、Service 路由失效但 Pod IP 仍可直連
Container Runtime (containerd) Worker Node 工人（真正落手做嘢） 拉取鏡像、啟動並運行容器（如 containerd, CRI-O） 容器無法 pull image、或者 run 唔起

2. 考試快速診斷心法 (30 秒排錯定律)

CKA 考試口訣：
  • Pod 卡喺 Pending ➜ 睇 kube-scheduler 或 Node 資源/Taints
  • Pod 卡喺 ContainerCreating / ImagePullBackOff ➜ 睇 kubelet, containerd 或網絡 CNI
  • Node 變成 NotReady ➜ 睇 Worker Node 上面嘅 systemctl status kubelet
  • Service 唔通但 Pod 直通 ➜ 睇 kube-proxy 同埋 iptables 規則
