Lesson 0015：kubeadm 起叢集（Killercoda 實戰）

目標：用 kubeadm 喺兩部 VM 上由零 init／join，將 0001 嗰張控制平面元件圖變成你親手裝出嚟嘅嘢：preflight、憑證、static pod、CNI，步步睇得見！

💡 點解呢課咁重要？
到 0014 為止，啲叢集全部係 kind「生」出嚟，你冇親手起過廠。CKA 要你識起、識 join、識裝 CNI——呢課喺 Killercoda 拋棄式 VM 度玩，整爛咗重建就得，本機 Calico 叢集完全唔受影響，夠貼地！
本課同 0016 都喺 Killercoda 進行

開 killercoda.com（免費瀏覽器練習場），揀個「kubeadm／Kubernetes cluster setup、含 control-plane＋worker 兩部 VM、Ubuntu 且已裝好 kubeadm/kubelet/kubectl」嘅場景。如果嗰場冇預裝 kubeadm，先照官方 Install kubeadm 頁裝：containerd／kubeadm／kubelet／kubectl 三步。玩完直接閂咗重建，本機叢集唔郁。

1. 睇下先：kubeadm init 背後做緊咩

記住呢條流程，考場填空啱晒用：

  • preflight：check root、CPU/記憶體、hostname、port 有冇被霸住。
  • 整憑證同 kubeconfig：CA 同各元件憑證（apiserver/controller-manager/scheduler/etcd/admin…）擺 /etc/kubernetes/pki；kubeconfig 擺 /etc/kubernetes。
  • 寫低控制平面 static pod manifest：/etc/kubernetes/manifests/ 下面出返 kube-apiserver.yaml、kube-controller-manager.yaml、kube-scheduler.yaml、etcd.yaml——kubelet 一見到就拉起佢哋（0014 嘅 etcd 就係咁樣活嘅）。
  • 派 bootstrap token：印出 join 指令，畀 worker 帶住 token 加入。
  • 等 CNI：未裝網路之前節點係 NotReady、coredns 卡住 Pending（0012 見過一模一樣嘅症狀）。

kubeadm join 就係 worker 端嘅鏡像流程：拎 token 同 apiserver 握手、問返張自己嘅憑證、kubelet 註冊上叢集。

2. HA 拓撲：兩種 etcd 擺法

Stacked etcd（疊放）External etcd（外置）
etcd 擺邊 同 control plane 同部機（每部 cp 各一份） 獨立嘅 etcd 主機群
機器需求 少（cp 幾部就有幾份 etcd） 多（cp + 獨立 etcd 群）
啱用 考試、中小叢集、實驗 生產、etcd 同 cp 要分開保養
🏭 港式比喻：起廠收樓一條龍
preflight＝收樓驗樓（水電煤、門鎖得唔得）；整 certs＋pki＝鎖匙房（每道門一把鎖匙）； 寫 manifests 起 static pod＝大廚返工（apiserver／scheduler／etcd 開爐）；admin.conf 拷去 ~/.kube＝收大門鎖匙； 裝 CNI＝拉電話線（唔拉就對外失聯）；join 指令＝QR code 邀請（worker 嘟一嘟入廠）。

🏗️ kubeadm 起廠流程圖：泳道時間線（由上而下落廠）

成個起廠得三步：config、CNI、join。邊步瀨嘢，對返個位就搵到原因。

路徑三寶＋網段門牌（考場默寫）
鎖匙房：/etc/kubernetes/pki/            ← CA＋各元件憑證
身份證：/etc/kubernetes/*.conf          ← admin.conf（大門鎖匙）／kubelet.conf／scheduler.conf…
廚房爐頭：/etc/kubernetes/manifests/     ← kube-apiserver.yaml／etcd.yaml…（kubelet 見檔開火）
門牌號段：--pod-network-cidr=192.168.0.0/16  ← 成條邨嘅門牌號段，Calico 派 Pod IP 靠佢；
         init 嗰陣唔畀＝之後冇網段可派，裝 CNI 都救唔返，要 reset 重嚟

3. 實作 A：kubeadm init + CNI

喺 control-plane VM 上 init
# 1. 先確認三件套就位（Killercoda 場景通常已裝好）
kubeadm version
kubelet --version
kubectl version --client

# 2. init：--pod-network-cidr 畀 Calico 用嘅網段（同 0012 對齊 192.168.0.0/16）
sudo kubeadm init --pod-network-cidr=192.168.0.0/16
#    成功後會印一大段：kubeconfig 設定步驟、join 指令、token
設定 kubectl（root 嘅 admin.conf 拷畀而家個 user）
# 3. kubeadm 將「管理員 kubeconfig」擺喺 /etc/kubernetes/admin.conf
#    拷去 $HOME/.kube/config 之後 kubectl 先認得叢集
mkdir -p $HOME/.kube
sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config

# 4. 睇成果：control-plane 已 Ready，但 worker 未 join、網路未裝
kubectl get nodes
kubectl get pods -n kube-system
#    coredns 卡 Pending、節點可能 NotReady——都係「未裝 CNI」嘅症狀
裝 CNI（Calico，v3.32.2，0012 同一套）
# 5. Calico operator 同 CRD、安裝設定——三支指令照抄
kubectl create -f https://raw.githubusercontent.com/projectcalico/calico/v3.32.2/manifests/v1_crd_projectcalico_org.yaml
kubectl create -f https://raw.githubusercontent.com/projectcalico/calico/v3.32.2/manifests/tigera-operator.yaml
kubectl create -f https://raw.githubusercontent.com/projectcalico/calico/v3.32.2/manifests/custom-resources.yaml

# 6. 等 calico-system 就緒，節點轉 Ready
kubectl get pods -n calico-system -w
kubectl get nodes
你應該觀察到咩

第 4 步到第 6 步係 0001 理論嘅完整重現：init 只裝控制平面，唔包網路；節點 NotReady、coredns Pending，直到 CNI 上線先全部轉好。親手起過一次，Troubleshooting 見到「NotReady + Pending」就會即刻諗起「先查 CNI」。

4. 實作 B：worker join + 驗收

喺 control-plane 上拎 join 指令
# 7. token 有時效（預設 24h）；過期就重新產生並直接印出完整 join 指令
#    （呢支指令要讀 root 嘅 admin.conf，非 root 記得加 sudo）
sudo kubeadm token create --print-join-command
#    輸出似：
#    kubeadm join 192.168.x.x:6443 --token xxxxxx.xxxxxxxxxxxxxxxx \
#        --discovery-token-ca-cert-hash sha256:xxxxxxxxxxxxxxxx
喺 worker VM 上執行 join
# 8. 將上一支指令嘅輸出（成段 kubeadm join ...）貼去 worker VM 執行
sudo kubeadm join 192.168.x.x:6443 --token xxxxxx.xxxxxxxxxxxxxxxx --discovery-token-ca-cert-hash sha256:xxxxxxxxxxxxxxxx
#    成功會印 "This node has joined the cluster"
返 control-plane 驗收
# 9. worker 出現喺節點清單、狀態 Ready
kubectl get nodes
kubectl get pods -A -o wide
#    calico-node 喺每部節點各一粒（0004 嘅 DaemonSet 現場）

# 10. 驗收：佈支 Deployment 跨節點跑，再刪走
kubectl create deployment demo --image=nginx:1.25 --replicas=3
kubectl get pods -o wide
kubectl delete deployment demo

5. 實作 C：加第二個 control plane（走查）

HA 控制平面要至少兩部 control-plane 同一個 load balancer（將 apiserver 流量分畀兩部 cp）。本課 Killercoda 場景通常得 2 部 VM，所以呢段係「走查」——睇明流程就得，唔使實跑：

多 cp 嘅 join 流程（概念走查）
# 喺第一部 cp init 嗰陣加 --control-plane-endpoint 指去 LB，並 --upload-certs
# 等憑證可以畀第二部 cp 下載：
sudo kubeadm init --pod-network-cidr=192.168.0.0/16 --control-plane-endpoint=lb.example.com:6443 --upload-certs

# 第一部 cp 印出嘅輸出入面，除咗 worker 嘅 join 指令，仲有一段「control-plane 專用」：
sudo kubeadm join lb.example.com:6443 --token xxxxxx --discovery-token-ca-cert-hash sha256:xxx --control-plane --certificate-key yyyyy

# --control-plane 話畀 kubeadm 知：「我係新嘅 control plane，唔係 worker」；
# --certificate-key 等佢解密第一部 cp 上傳嘅憑證
考場小抄

① init 後三件事：set kubeconfig（admin.conf → ~/.kube/config）、裝 CNI、join worker——口訣「config、CNI、join」。② token 過期：kubeadm token create --print-join-command 一行搞掂。③ 憑證喺 /etc/kubernetes/pki，各 kubeconfig 喺 /etc/kubernetes；admin.conf 係管理員嗰把。④ 控制平面元件 = /etc/kubernetes/manifests/ 下面嘅 static pod。⑤ 多 cp：init 加 --control-plane-endpoint（LB）同 --upload-certs，join 加 --control-plane --certificate-key。⑥ 節點 NotReady：九成係 CNI 未裝或者 CNI pod 未起身。

本課戰果

  • 你喺 Killercoda 乾淨 VM 上用 kubeadm init 起出控制平面，講得出 init 背後每步。
  • 你 set 好 admin kubeconfig、裝上 Calico CNI，見到節點由 NotReady 轉 Ready。
  • 你用 kubeadm token create --print-join-command 等 worker join 咗再驗收。
  • 你走查咗第二個 control plane 嘅 join 流程，識分 stacked 同 external etcd 兩種 HA 拓撲。
