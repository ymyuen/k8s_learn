1. 睇下先：三種「交 YAML」嘅方法

HelmKustomize原生 YAML＋kubectl
本質 套件管理員（chart＝模板＋values） 宣告式「基底＋疊加」 一份份寫死嘅檔案
換環境 --set 或換 values 檔 換 overlay 目錄 copy 一份改（最易出事）
回滾／卸載 helm rollback／uninstall 冇 release 概念（靠 kubectl） 冇（自己刪）
啱用 裝大型第三方套件（數據庫、監控） 自己維護嘅一組 YAML 要分環境 極簡、單一物件練習

一句記住：Helm 管「套件同版本」，Kustomize 管「同一份 YAML 嘅環境差異」。

🍜 港式比喻三連
Helm＝IKEA 成套傢俬／App Store 一鍵裝（chart 係說明書＋零件，release 係你屋企砌好嗰套，唔啱 rollback 換返舊款）； Kustomize＝透明膠片疊圖（base 係底圖唔郁，overlay 係上面嗰塊膠片，只畫差異，疊埋就係 final）； CRD＝寵物登記處學新字（未登記「龍貓」之前，表格唔識呢隻字；登記咗先交得表，但未請飼養員之前只係一張紙）。

📦 三寶流程圖：Helm 回滾＋Kustomize 疊片＋CRD 登記鏈

揀架生好簡單：裝人哋嘅大件嘢用 Helm，派生自己嘅多環境用 Kustomize，自創資源先用 CRD＋Operator。

指令食咩幾時用
kubectl apply -f散紙：單一／多份 YAML 檔極簡練習、CRD／CR 逐份交（本課實作 C）
kubectl apply -k成個 folder：含 kustomization.yaml 嘅目錄base／overlay 疊加（本課實作 B）
kubectl kustomize 目錄唔 apply，淨係印合併結果preview 神器：先睇 final 啱唔啱再 -k

2. 實作 A：Helm 裝一套 nginx

喺本機裝 helm（官方安裝腳本，一次性）
# 1. 先確認叢集仲喺度（0012–0014 嘅 Calico 雙節點；若唔喺，用 0012 嘅 kind-calico.yaml 重建）
kubectl get nodes

# 2. 下載並執行官方安裝腳本（get-helm-3）
curl -fsSL -o get_helm.sh https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3
chmod 700 get_helm.sh
./get_helm.sh
helm version
加 repo、搜尋、安裝
# 3. 加入 Bitnami 嘅 chart repo（Helm 嘅「軟件來源」）
#    Bitnami 而家都提供 OCI registry（oci://registry-1.docker.io/bitnamicharts），
#    本課用傳統 repo 教學；兩者指令語法略有唔同
helm repo add bitnami https://charts.bitnami.com/bitnami
helm repo update

# 4. 搜尋 repo 入面嘅 chart；-l 列出全部版本，揀個「釘版」安裝（--version）
helm search repo bitnami/nginx --versions | head -n 5
helm search repo bitnami/nginx

# 5. 安裝：release 名叫 myweb，chart 係 bitnami/nginx
#    （chart 會展開成 Deployment/Service/…成組 YAML 送入叢集）
#    入版控嘅團隊會釘 chart 版本：helm install myweb bitnami/nginx --version <上一步睇到嘅版號>
helm install myweb bitnami/nginx
helm list

# 6. 用 helm 嘅 label 睇佢到底起咗咩
kubectl get all -l app.kubernetes.io/instance=myweb
--set 覆寫、升級、回滾、卸載
# 7. 用 --set 覆寫 chart 嘅預設值（每個 chart 嘅 keys 以 helm show values 輸出為準）
helm show values bitnami/nginx | grep -A4 -i 'replicaCount\|service:'
helm upgrade myweb bitnami/nginx --set replicaCount=3
kubectl get pods -l app.kubernetes.io/instance=myweb
#    副本由 1 變 3

# 8. 睇 release 嘅版本歷史
helm history myweb

# 9. 回滾去第一個版本（revision 1）——Helm 版嘅 rollout undo
helm rollback myweb 1
kubectl get pods -l app.kubernetes.io/instance=myweb

# 10. 卸載：將 chart 起出嚟嘅嘢一次清光
helm uninstall myweb
helm list
你應該觀察到咩

Helm 嘅核心價值喺第 10 步：一次卸載，全部清走——所有由 chart 起嘅物件都帶 app.kubernetes.io/instance=myweb，helm 靠呢個回收。如果某個 chart 嘅 --set 鍵名同呢度唔同，helm show values bitnami/nginx 會印出完整可 set 清單——照佢為準。

3. 實作 B：Kustomize——基底同疊加

建立 base（基底）
# 11. 用 0004 嘅 dry-run 打法產出 Deployment 同 Service，擺入 kustom/base/
mkdir -p kustom/base kustom/overlays/prod
kubectl create deployment kustom-demo --image=nginx:1.25 --replicas=1 --dry-run=client -o yaml > kustom/base/deployment.yaml
kubectl create service clusterip kustom-demo --tcp=80:80 --dry-run=client -o yaml > kustom/base/service.yaml

# 12. base 嘅 kustomization.yaml：宣告「基底包含邊啲檔」
nano kustom/base/kustomization.yaml
# 內容：
# apiVersion: kustomize.config.k8s.io/v1beta1
# kind: Kustomization
# resources:
# - deployment.yaml
# - service.yaml
預覽並套用 base
# 13. kubectl kustomize 直接印出合併後嘅完整 YAML（kustomize 嘅「dry-run」）
kubectl kustomize kustom/base | head -n 30

# 14. -k 就係「apply 呢個 kustomization」
kubectl apply -k kustom/base
kubectl get deploy,svc kustom-demo
prod overlay：只疊加「副本數變 3」
# 15. overlay 嘅 kustomization.yaml：resources 指去 ../../base，再疊 patches
nano kustom/overlays/prod/kustomization.yaml
# 內容：
# apiVersion: kustomize.config.k8s.io/v1beta1
# kind: Kustomization
# resources:
# - ../../base
# replicas:
# - name: kustom-demo
#   count: 3

# 16. 預覽 prod 版：得 replicas 嗰行被改成 3
kubectl kustomize kustom/overlays/prod | grep -E 'name:|replicas:'
kubectl apply -k kustom/overlays/prod
kubectl get deploy kustom-demo
#    DESIRED 變成 3——基底冇郁，prod 疊加上咗

# 17. 收尾
kubectl delete -k kustom/overlays/prod
rm -rf kustom
你應該觀察到咩

Kustomize 唔寫模板、唔改原檔：base 係一份「乾淨版」，overlay 只講「差異」。第 16 步嘅 kubectl kustomize 係佢嘅殺手鐧——先睇合併結果再套用。CKA 鍾考 -k（kustomization）同 -f（單一/多份 YAML）嘅分別。

4. 實作 C：CRD、Custom Resource 同 Operator

Kubernetes 嘅 API 可以「生出新品種」：用 CRD（CustomResourceDefinition）定義個新資源型別，之後 kubectl apply 嗰種型別嘅物件——Custom Resource（自訂資源）。但留意：CR 存入 etcd 之後，冇 controller 嘅話佢就只係「一筆數據」，冇人會照佢個 spec 去起 Deployment。Operator 就係「會睇某種 CR、將佢變成實際資源」嘅控制器（0002 學嘅控制器模式，延伸去自訂資源）。

crd-widgets.yaml — 定義「Widget」型別
# crd-widgets.yaml — 宣告新資源型別：group example.com，kind Widget
apiVersion: apiextensions.k8s.io/v1
kind: CustomResourceDefinition
metadata:
  name: widgets.example.com
spec:
  group: example.com
  names:
    kind: Widget
    listKind: WidgetList
    plural: widgets
    singular: widget
  scope: Namespaced
  versions:
  - name: v1
    served: true
    storage: true
    schema:
      openAPIV3Schema:
        type: object
        properties:
          spec:
            type: object
            properties:
              replicas:
                type: integer
套用 CRD，識返個新資源
# 18. 套用 CRD
nano crd-widgets.yaml
kubectl apply -f crd-widgets.yaml
kubectl get crd widgets.example.com

# 19. 由呢刻起，kubectl 識得 widgets 呢個資源
kubectl api-resources | grep widgets
cr-widget.yaml — 起個 Widget 實例
# cr-widget.yaml — apiVersion = <group>/<version>，kind = Widget
apiVersion: example.com/v1
kind: Widget
metadata:
  name: my-widget
spec:
  replicas: 3
套用、查詢、刪除
# 20. 套用 CR——apiserver 照收、存入 etcd
nano cr-widget.yaml
kubectl apply -f cr-widget.yaml
kubectl get widgets
kubectl get widget my-widget -o yaml
#    留意：冇任何 Pod 被起出嚟——因為冇 controller 睇住 Widget

# 21. 收尾：刪 CR 同 CRD
kubectl delete -f cr-widget.yaml
kubectl delete -f crd-widgets.yaml
rm -f crd-widgets.yaml cr-widget.yaml get_helm.sh
kubectl get nodes
你應該觀察到咩

第 20 步係明 Operator 嘅鎖匙：CR 只係數據，Controller 先係行為。真實世界嘅 Operator（如 prometheus-operator）會 watch「Prometheus 型 CR」，再幫你起返 Deployment、Service、RBAC 成組。你等如行到「自己寫控制器」嘅邊界——將 CRD＋CR 呢段練熟，就明 Operator 做緊咩。

5. 三個介面收埋：CNI、CSI、CRI

Kubernetes 用三個「標準介面」外判底層實作，一路行嚟你都掂過：

介面管咩本課程掂過嘅實作
CNIPod 網路（IP 同連通性）kindnet（0012 之前）、Calico（0012 起）
CSI儲存（掛磁碟）kind 內建 local-path（0008）
CRI容器執行時期containerd（kind／kubeadm 都用佢）

口訣：CNI 管網、CSI 管存、CRI 管跑。

考場小抄

① Helm：repo add → install → upgrade --set → history／rollback → uninstall；release 係「一次安裝」嘅單位。② -k 食 kustomization 目錄、-f 食 YAML 檔；kubectl kustomize 目錄 可預覽。③ CRD 三步次序：先 apply CRD → 再 apply CR → 最後（若果有）controller 先反應。④ CR 嘅 apiVersion 係「group/version」（example.com/v1），唔係固定嗰幾個。⑤ 冇 controller 嘅 CR 只係一筆數據。⑥ 三介面口訣：CNI 網、CSI 存、CRI 跑。

本課戰果

  • 你裝好 Helm，完成 install／--set 升級／rollback／uninstall 成個圈。
  • 你用 Kustomize 嘅 base＋overlay 做到「基底唔郁、prod 疊加」，仲用 -k 套用。
  • 你寫出極簡 CRD 同 CR，親眼見到「冇 controller 嘅 CR 只係數據」。
  • 你將 CNI／CSI／CRI 三介面收埋入同一張表。
