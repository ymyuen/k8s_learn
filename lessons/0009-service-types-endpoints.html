Lesson 0009：Service 同 Endpoints：唔變嘅存取門口

目標：搞掂 Service 呢個「唔會變嘅 VIP 門口」——識用 selector 射中 Pod、睇明 Endpoints 名單點自動更新，再親手行通 ClusterIP、NodePort 同 Headless 三條路。考場見到 Service 唔通，一眼知係邊層瀨嘢！

💡 點解呢課咁重要？
Pod 嘅 IP 成日生生死死、轉頭就換，你唔可以叫成個叢集背 IP 嚟搵人。Service 就係嗰個「貼地門牌」——Pod 換咗幾多次，客都係打同一個 VIP。呢個 selector → Endpoints → 轉發嘅諗法，係成個 Phase 3 嘅地基，DNS、Ingress、NetworkPolicy 全部建喺佢上面！

1. Service 嘅組成：selector → Endpoints → 轉發

入到 Phase 3（Services & Networking，20%）。之前啲 Pod 各有各活：0008 你見過 Pod 可以死、資料唔會死——咁「人哋點搵到佢」呢？答案就係 Service：一個唔跟 Pod 變嘅虛擬 IP（VIP）門口，selector 射中邊幾粒 Pod，佢就將流量交畀邊個。今課先建立「Service 思維」，下課再加 DNS。今課部機沿用 0008 嗰個雙節點叢集。

🚪 Service 雙線圖：控制線（虛線）vs 數據線（實線）

點讀呢幅圖：上面虛線係「換名單」嘅過程（Pod 死 → 名單換 → 規則重寫），下面實線係「行流量」嘅過程（客永遠打同一個 VIP）。兩條線分開睇，就唔會再以為 Service 自己會轉發封包。

Service 將流量交畀生勾勾嘅 Pod（概念圖）
              Service（穩定 VIP：10.96.x.x）
                     │ selector: app=web
                     ▼
              Endpoints（此刻嘅 Pod IP 名單）
                ├── 10.244.0.5:80
                └── 10.244.1.7:80
                     │ kube-proxy 喺每粒節點寫 iptables/IPVS 規則
                     ▼
             流量轉去名單上嘅 Pod（會輪流）

Service 自己唔做轉發——真正落手做嘅係每粒節點上面嘅 kube-proxy：佢 watch 住 Service 同 Endpoints，將「去 VIP:Port 嘅封包」改寫成「去某粒 Pod IP:Port」。kube-proxy 有兩種行法：iptables（預設，規則式）同 IPVS（核心內置嘅負載平衡，規則多嗰陣效能好啲）——概念知就得，考試多數只問「邊個喺節點上面實作 Service 規則」＝ kube-proxy。

2. Service 四大類型，一表睇晒

類型對外範圍一句話
ClusterIP（預設） 叢集內 只畀叢集內互相嗌用嘅 VIP
NodePort 叢集外（靠節點 IP） ClusterIP ＋ 每粒節點開個 30000–32767 嘅 port 收外面流量
LoadBalancer 叢集外（雲端） NodePort ＋ 雲幫你生個對外負載平衡器（kind 冇雲，要 MetalLB 等）
ExternalName — 純 DNS 嘅 CNAME 轉址，冇 VIP 亦冇 selector
VIP 經典考點：ping 唔通、curl 通

ClusterIP 係「iptables 規則做出嚟嘅假 IP」，唔係某部機上面嘅真網卡——所以 ping <VIP>（ICMP）一定唔通，但 curl http://<VIP>/（TCP）會通。考試如果有人用「ping 唔通即係 Service 爛咗」嚟考你，答案係：ping 唔通係正常，要用 TCP 嚟測。

3. 實作 A：ClusterIP 同 Endpoints 連動

佈署、暴露、睇三樣嘢
# 1. 佈 2 粒 nginx（0002 嘅老朋友）
kubectl create deployment web --image=nginx:1.25 --replicas=2
kubectl rollout status deployment/web

# 2. expose 成 Service：冇畀 --type 即係 ClusterIP；--port=80 會自動捉 containerPort
kubectl expose deployment web --port=80

# 3. 睇 Service：CLUSTER-IP 就係嗰個「唔會變嘅 VIP」
kubectl get svc web

# 4. 睇 Endpoints：同名嘅 endpoints 物件列出此刻 2 粒 Pod 嘅 IP
kubectl get endpoints web
kubectl get pods -o wide -l app=web
#    對一對：Endpoints 嘅 IP 就係嗰 2 粒 Pod 嘅 IP
由叢集內打 VIP
# 5. 起粒長駐嘅 busybox 做「客」（0009–0010 都要用）
kubectl run client --image=busybox:1.36 --restart=Never -- sleep 3600
kubectl wait --for=condition=Ready pod/client

# 6. 將 VIP 存入變數，用 wget 打佢（回 nginx 嘅 200 歡迎頁）
VIP=$(kubectl get svc web -o jsonpath='{.spec.clusterIP}')
echo $VIP
kubectl exec client -- wget -qO- "http://$VIP/" | head -n 5
斬走一粒 Pod，睇 Endpoints 自己更新
# 7. 揀粒 Pod 刪走，即刻再睇 Endpoints
kubectl delete pod web-(隨機尾碼)

# 8. -w 睇 Endpoints 變化：舊 IP 消失，新 Pod Ready 之後新 IP 補上
kubectl get endpoints web -w
#    想親眼睇交替：開兩個 terminal，一邊跑呢行、另一邊去刪 Pod（Ctrl+C 結束）
你應該觀察到咩

第 4 步就係「Service 嘅真相」：佢冇自己嘅後端，selector 射中幾粒 Pod，Endpoints 就列幾個 IP。第 7–8 步係成個機制嘅精髓——Pod 換 IP、Service 唔使郁，Endpoints 控制器自動將名單換新，而你個客永遠只需要記住個 VIP。

🚶‍♂️ 四步眼見為憑（跟住行一次，真 IP 版）：
  1. 攞 VIP（唔變電話）：kubectl get svc web → CLUSTER-IP 10.96.123.45。抄低佢，之後三步佢一個字都唔會變。
  2. 攞當更名單：kubectl get endpoints web → 10.244.0.5:80, 10.244.1.7:80；再 kubectl get pods -o wide -l app=web 對一對——Endpoints 嘅 IP 就係嗰兩粒 Pod 嘅 IP。
  3. 斬一粒 Pod：kubectl delete pod web-xyz。唔使驚，Deployment 會即刻補返粒新嘅（例如 10.244.1.8）。
  4. 睇換紙全程：kubectl get endpoints web -w 會見到舊 IP 變 Terminating 消失、新 IP 出現；再 echo $VIP——仲係 10.96.123.45，個客 wget http://$VIP/ 照樣 200！

🐳 Docker -p 祖先 vs K8s VIP：docker run -p 8080:80 係「部機開個真 port 對應個 container」——部機死，個 mapping 就冇。K8s Service 係再上一層嘅「虛擬電話」：VIP 唔綁任何一粒 Node，靠每粒 Node 嘅 kube-proxy 各自寫 iptables 實現。所以 Pod 換、Node 換，個電話都唔使換——呢層就係 K8s 比 Docker 多出嚟嘅穩定層。

4. 實作 B：NodePort——將服務開到節點門口

ClusterIP 只活喺叢集入面；NodePort 喺每粒節點開個 30000–32767 嘅 port，外面（例如你部主機）打「節點 IP:嗰個 port」就入到嚟。真正由 host 連入去嘅示範留返 0011（嗰課會重建有 port mapping 嘅叢集），呢度先喺叢集內驗證條路係通嘅。

將 Service 升級做 NodePort
# 9. 刪走舊 ClusterIP Service，轉用 NodePort 重開（乾淨示範）
kubectl delete service web
kubectl expose deployment web --type=NodePort --port=80 --name=web-np

# 10. NODE(S) 欄：系統由 30000–32767 隨機派一個（例如 31234）
kubectl get svc web-np

# 11. 查節點嘅 IP（INTERNAL-IP）
kubectl get nodes -o wide
#    記低 kind-worker（或 control-plane）嘅 INTERNAL-IP，例如 172.18.0.3
喺叢集內行「外面入嚟嗰條路」
# 12. 用變數砌出 NodeIP:NodePort，由 client pod 打
NODEIP=$(kubectl get nodes -o jsonpath='{.items[0].status.addresses[?(@.type=="InternalIP")].address}')
NODEPORT=$(kubectl get svc web-np -o jsonpath='{.spec.ports[0].nodePort}')
kubectl exec client -- wget -qO- "http://$NODEIP:$NODEPORT/" | head -n 5
#    回 200 即係 NodePort 條路通咗：封包 → 節點 port → iptables → 某粒 Pod

# 13. 驗證「邊粒節點嘅 NodePort 都到」：轉 control-plane 嘅 IP 再打一次
NODEIP2=$(kubectl get nodes -o jsonpath='{.items[1].status.addresses[?(@.type=="InternalIP")].address}')
kubectl exec client -- wget -qO- "http://$NODEIP2:$NODEPORT/" | head -n 5
你應該觀察到咩

第 13 步係關鍵：NodePort 係「每粒節點都開同一個 port、各自將流量轉入叢集」，所以無論打邊粒節點嘅 IP 都會通。LoadBalancer 其實就係「雲整部 LB，將流量送入任何一粒節點嘅 NodePort」——你識咗 NodePort，LoadBalancer 底層就明咗。

5. 實作 C：Headless Service——唔要 VIP，直接畀 IP 名單

有啲場合（數據庫主從、StatefulSet）唔想行「VIP ＋ 隨機轉發」，想「DNS 直接回每粒 Pod 嘅 IP」。將 Service 嘅 clusterIP 設做 None，就係 Headless Service：唔派 VIP、唔轉發，只負責將 selector 命中清單餵畀 DNS（細節下堂）。

起個 headless Service
# 14. expose 嗰陣帶 --cluster-ip=None
kubectl expose deployment web --type=ClusterIP --name=web-hd --port=80 --cluster-ip=None

# 15. CLUSTER-IP 顯示 None
kubectl get svc web-hd

# 16. Endpoints 照樣列出身後 2 粒 Pod（headless 冇 VIP，但 selector 照常運作）
kubectl get endpoints web-hd

# 17. 收尾：刪走練習物件（留返 client 畀下堂）
kubectl delete deployment web
kubectl delete svc web-np web-hd
kubectl get pods,svc,endpoints
考場小抄

① 起：kubectl expose deployment NAME --port=80 [--type=NodePort|LoadBalancer|ClusterIP]；快版 kubectl create service nodeport NAME --tcp=80:80。② 查後端：kubectl get endpoints NAME（連 Service 同名嘅 endpoints）對返 get pods -o wide。③ 除錯口訣：Service 唔通先查「selector 有冇射中 Pod」——get endpoints 吉嘅即係冇射中；再查 Pod 嘅 readiness（0007 嘅 READY 0/1）。④ NodePort 範圍 30000–32767。⑤ VIP ping 唔通好正常，用 TCP 測。⑥ kube-proxy 係「喺節點上面實作 Service 規則」嗰個人。

本課戰果

  • 你識用 expose 起 ClusterIP Service，睇得明「selector → Endpoints → kube-proxy」條轉發鏈。
  • 你親眼見到斬 Pod 之後 Endpoints 自動換新，Service 個 VIP 由頭到尾冇變過。
  • 你用 NodePort 行通「外面 → 節點 → Pod」條路，仲驗證邊粒節點嘅 port 都通。
  • 你起咗 headless Service，睇得明佢「唔要 VIP、淨畀 IP 名單」嘅定位。

小測驗

Service 嘅 selector 射中邊啲 Pod，會反映喺邊個物件？

ClusterIP 個 VIP 點解 ping 唔通？

邊個喺每粒節點上面實作 Service 轉發規則？
