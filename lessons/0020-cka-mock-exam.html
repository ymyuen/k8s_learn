Lesson 0020：CKA 模擬考同衝刺策略

目標：課程最後一課：一場 60 分鐘、10 題嘅計時模擬考，覆蓋 0002–0019 全部重點。考完對答案、錯題回課、再讀「一頁濃縮小抄」——之後你就有料喺真考試（2 小時、查得官方文件、Killer.sh 17 題模擬）入面攞好成績。

💡 點解呢課咁重要？
學咗 19 課唔等於考得掂——CKA 考嘅係速度同臨場反應！呢場模擬考就係你嘅試金石：60 分鐘內睇下自己邊度仲瀨嘢，邊度已經搞掂。貼地練一次，好過齋睇十次筆記！
模擬考規則（睇完先開波）

① 計時 60 分鐘，10 題，每題約 6 分鐘。② 全程喺 WSL2 bash、本地 Calico 叢集操作（第 8 題備份檔擺 ~/practice）。③ 查得官方文件，但唔准停低睇課文——寫完先對答案。④ 每題下面有「驗收指令」，自己判斷過唔過。⑤ 另開一個 ~/practice/mock-notes.txt 記低「邊題卡住、卡喺邊」。

📋 60 分鐘 Kanban 戰鬥板：TODO → DOING → VERIFIED / SKIPPED

唔好將 10 題當直線跑，要當 Kanban 玩：DOING 永遠只得 1 張卡，卡住 5:00 即寫低題號掟去 SKIPPED。

記住：先易後難、唔纏鬥、做完即驗收——時間先係最大嘅敵人。⏱️ 熔斷規則：5:00 卡住寫低題號下一題（寫喺 ~/practice/mock-notes.txt），唔准坐喺度發吽哣。

1. 實作 A：10 題計時模擬考

撳錶開波！下面 10 題覆蓋成個課程，做唔切都唔好偷睇住。開波前先學識呢招 dry-run 填空法——唔使背成份 YAML，畀 kubectl 幫你寫骨架，你填關鍵格就得。

✍️ dry-run 填空法：骨架佢寫，答案你填（Q4／Q7／Q10 必用）

🐳 Docker 老朋友：--dry-run=client -o yaml 就係「幫你寫 Dockerfile 骨架嗰個朋友」——FROM、COPY 幫你排好，你淨係改 APP 名同 port。K8s 一樣：骨架自動出，你填 ___BLANK___ 嗰幾格。

題目骨架指令（已喺題目）填邊格 ___BLANK___explain 查詢
Q4 env-checkkubectl run … --dry-run=client -o yamlenvFrom: configMapRef: ___BLANK___(app-env)
env.valueFrom.secretKeyRef: ___BLANK___		kubectl explain pod.spec.containers.envFrom
Q7 pv-podkubectl run pv-pod … --dry-run=client -o yamlvolumeMounts.mountPath: ___BLANK___(/data)
volumes.persistentVolumeClaim.claimName: ___BLANK___		kubectl explain pod.spec.volumes.persistentVolumeClaim

backend.service.port.number: ___BLANK___(80)		kubectl explain ingress.spec.rules.http.paths.backend

考場動作：dry-run 出骨架 → explain 對串字 → nano 填 BLANK → apply → 驗收指令撳多次。Q4／Q7／Q10 唔係考背書，係考你識唔識填表。

題 1（0002 溫習）Deployment 更新同回滾
# 1. 需求：開 deployment web（nginx:1.25、3 副本）；升上 nginx:1.26 並確認 rollout 成功；再回滾返上一版。
kubectl create deployment web --image=nginx:1.25 --replicas=3
kubectl set image deployment/web web=nginx:1.26
kubectl rollout status deployment/web
kubectl rollout undo deployment/web
#    驗收：kubectl rollout history deployment/web 有 ≥3 個 REVISION；get pods 3 粒 Running
題 2（0009 溫習）將服務開成 NodePort
# 2. 需求：將題 1 嘅 deployment/web 暴露成 NodePort Service（port 80），確認 Endpoints 有 3 個 IP。
kubectl expose deployment web --type=NodePort --port=80 --name=web-np
#    驗收：kubectl get svc web-np（TYPE=NodePort）；kubectl get endpoints web-np 有 3 個 IP
題 3（0004 溫習）Job 同 CronJob
# 3. 需求：a) 用 kubectl create job 開一支跑完即走嘅 Job（busybox 印 hello）；b) 開每 2 分鐘跑一次嘅 CronJob。
kubectl create job hello-job --image=busybox:1.36 -- echo hello-cka
kubectl create cronjob every-2min --image=busybox:1.36 --schedule="*/2 * * * *" -- date
#    驗收：a) get jobs → COMPLETIONS 1/1，kubectl logs job/hello-job 有 hello-cka
#          b) get cronjob 睇到 SCHEDULE；等 2 分鐘 get jobs 出現 every-2min-xxx
題 4（0006 溫習）ConfigMap 同 Secret 注入
# 4. 需求：a) configmap app-env（APP_ENV=staging）；b) secret db-secret（DB_PASSWORD=secret123）；
#            c) 一粒 pod 將兩者都掛成環境變數並印出嚟。
kubectl create configmap app-env --from-literal=APP_ENV=staging
kubectl create secret generic db-secret --from-literal=DB_PASSWORD=secret123
kubectl run env-check --image=busybox:1.36 --restart=Never --dry-run=client -o yaml -- sleep 3600 > env-check.yaml
#    nano 手動加：envFrom.configMapRef（app-env）＋ env.valueFrom.secretKeyRef（DB_PASSWORD）
kubectl apply -f env-check.yaml
#    驗收：kubectl exec env-check -- sh -c 'echo $APP_ENV $DB_PASSWORD' → staging secret123
題 5（0013 溫習）RBAC
# 5. 需求：namespace team-a 開 SA deployer；授權佢喺 team-a 內對 deployments 可以
#           get/list/create/update；用 auth can-i 驗證 get=yes、delete=no、kube-system 嘅 get=no。
kubectl create ns team-a
kubectl -n team-a create serviceaccount deployer
kubectl -n team-a create role deployer-role --verb=get,list,create,update --resource=deployments
kubectl -n team-a create rolebinding deployer-bind --role=deployer-role --serviceaccount=team-a:deployer
#    驗收：三行 auth can-i（--as=system:serviceaccount:team-a:deployer）
題 6（0012 溫習）NetworkPolicy
# 6. 需求：namespace app 內三粒 pod（app=a、app=b、app=x），app=b 跑 nginx。
#           NetworkPolicy：只准 app=a 連到 app=b 嘅 80，其餘全擋。
#           先開資源，再落 default-deny＋精準放行（0012 兩招）。
kubectl create ns app
kubectl -n app run app-b --image=nginx:1.25 --labels=app=b --restart=Never --port=80
kubectl -n app expose pod app-b --port=80
kubectl -n app run app-a --image=busybox:1.36 --labels=app=a --restart=Never -- sleep 3600
kubectl -n app run app-x --image=busybox:1.36 --labels=app=x --restart=Never -- sleep 3600
kubectl apply -f - <<'EOF'
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-a-to-b
  namespace: app
spec:
  podSelector:
    matchLabels:
      app: b
  policyTypes: ["Ingress"]
  ingress:
  - from:
    - podSelector:
        matchLabels:
          app: a
    ports:
    - protocol: TCP
      port: 80
EOF
#    驗收：exec app-a 連 http://app-b 通；exec app-x 連 http://app-b 逾時
題 7（0008 溫習）靜態 PV + PVC
# 7. 需求：hostPath PV（kind-worker 嘅 /mnt/mock、1Gi、Retain、storageClassName ""）
#           + 同名嘅 PVC 綁定成功；掛入 pod 後寫到檔。
docker exec kind-worker mkdir -p /mnt/mock
kubectl apply -f - <<'EOF'
apiVersion: v1
kind: PersistentVolume
metadata:
  name: pv-mock
spec:
  capacity: {storage: 1Gi}
  accessModes: ["ReadWriteOnce"]
  persistentVolumeReclaimPolicy: Retain
  storageClassName: ""
  hostPath: {path: /mnt/mock, type: DirectoryOrCreate}
  nodeAffinity:
    required:
      nodeSelectorTerms:
      - matchExpressions:
        - key: kubernetes.io/hostname
          operator: In
          values: ["kind-worker"]
EOF
kubectl apply -f - <<'EOF'
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: pvc-mock
spec:
  accessModes: ["ReadWriteOnce"]
  storageClassName: ""
  resources: {requests: {storage: 1Gi}}
EOF
kubectl run pv-pod --image=busybox:1.36 --restart=Never --dry-run=client -o yaml -- sleep 3600 > pv-pod.yaml
#    nano 手動加 volume/volumeMount（claimName: pvc-mock，mountPath: /data）
kubectl apply -f pv-pod.yaml
#    驗收：get pvc → Bound；exec pv-pod 寫到讀返 /data/mock.txt
題 8（0014 溫習）etcd snapshot
# 8. 需求：對本地 etcd 存 snapshot 到 /var/lib/etcd/etcd-mock.db、拷返 host，並用 snapshot status 驗證。
kubectl exec -n kube-system etcd-kind-control-plane -- sh -c 'ETCDCTL_API=3 etcdctl --endpoints=https://127.0.0.1:2379 --cacert=/etc/kubernetes/pki/etcd/ca.crt --cert=/etc/kubernetes/pki/etcd/server.crt --key=/etc/kubernetes/pki/etcd/server.key snapshot save /var/lib/etcd/etcd-mock.db'
docker cp kind-control-plane:/var/lib/etcd/etcd-mock.db ~/practice/etcd-mock.db
kubectl exec -n kube-system etcd-kind-control-plane -- sh -c 'ETCDCTL_API=3 etcdctl snapshot status /var/lib/etcd/etcd-mock.db --write-out=table'
#    驗收：status table 有 HASH/REVISION/TOTAL KEYS；host 上 ls -lh 睇到檔案
題 9（0016 溫習）節點維護
# 9. 需求：將 kind-worker cordon，確認唔排得新 Pod 之後再 uncordon 復原。
kubectl cordon kind-worker
kubectl get nodes
kubectl uncordon kind-worker
kubectl get nodes
#    驗收：cordon 後 STATUS 出現 SchedulingDisabled；uncordon 後消失
題 10（0011 溫習）Ingress 資源
# 10. 需求：寫一份 Ingress（ingressClassName: nginx）將 /demo 導去題 2 嘅 web-np:80。
#          本地 Calico 叢集冇 ingress 控制器，呢題練「寫啱資源」——
#          apply 成功＋describe 冇 schema 錯誤即當過（ADDRESS 留空係預期）。
kubectl apply -f - <<'EOF'
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: mock-ingress
spec:
  ingressClassName: nginx
  rules:
  - http:
      paths:
      - path: /demo
        pathType: Prefix
        backend:
          service:
            name: web-np
            port:
              number: 80
EOF
#    驗收：kubectl get ingress mock-ingress 睇到規則；describe 冇 error

3. 實作 C：考前 checklist（考前三日逐項剔）

  • 文件書籤：將官方文件加書籤兼練熟「喺考試介面點開」——kubectl Cheat Sheet、Deployment、Service、NetworkPolicy、PV、RBAC、etcd、kubeadm。真考試查得官方文件，知去邊度搵快過背晒佢。
  • 別名同環境：alias k=kubectl、export do="--dry-run=client -o yaml"、complete -F __start_kubectl k（bash completion）——開考第一分鐘搞掂佢。
  • 加速反射：dry-run 出 YAML 再改（0004 起練到爛）、-o wide、kubectl explain 補欄位記憶。
  • 時間策略：先掃晒成卷，先做有把握嗰啲；單題卡超過 5 分鐘即跳，最後先返嚟。
  • Killer.sh：買考試包 2 次（每次 36 小時），考前一至兩星期各做一次，錯題返去上面對照表。

全 20 課濃縮
# 四控制器口訣（0004）：
Deployment 補數量、DaemonSet 補節點、Job 補失敗、CronJob 補時間

# Workloads（0005–0007）：
requests 排程／limits 執行；QoS：全等=Guaranteed、全冇=BestEffort
taint 打節點、toleration 寫 Pod，效果 NoSchedule／PreferNoSchedule／NoExecute
liveness 失敗=重啟、readiness 失敗=摘流量；HPA 前提=metrics-server+requests

# Config & Storage（0006、0008）：
Secret base64 ≠ 加密；volume 掛載約 1 分鐘內同步、env 唔更新
PVC 係請求、PV 係現貨、StorageClass 係工廠；RWO/ROX/RWX

# Networking（0009–0012）：
Service：selector→Endpoints→kube-proxy；NodePort 30000–32767
FQDN = svc.ns.svc.cluster.local；DNS 有回應 ≠ 後端可用
Ingress＝規則／IngressClass＝指名／Controller＝執行者
NetworkPolicy：規則出現即預設拒絕；podSelector{}＝全選；egress 唔好漏 DNS

# 叢集管理（0013–0017）：
RBAC：Role×RoleBinding=ns、ClusterRole×RoleBinding=限返 ns、
      ClusterRole×ClusterRoleBinding=全叢集；auth can-i 萬用
etcd：save→status→restore 三模板；路徑 /etc/kubernetes/manifests、/var/lib/etcd
升級：cp 先 node 後、一次一小版；drain --ignore-daemonsets；cordon 唔搬屋
Helm 管套件、Kustomize 管差異；CRD 先於 CR 於 controller

# 除錯（0018–0019）：
get → describe → logs(→--previous) → exec
Exit 137 = OOM；CrashLoop 睇 --previous；Pending 睇 Events
Service 唔通：DNS→endpoints→READY→NetworkPolicy 四站檢查
考場小抄（最後一張）

① 時間係最大敵人：先易後難、唔好纏鬥、題目叫「apply」就 apply、叫「睇狀態」就唔好多手。② 指令唔記得參數：kubectl create ... --help 同 kubectl explain pod.spec.containers 係合法嘅官方查詢。③ 每題做完用題目畀嘅驗證方法確認一次（get／describe／logs）。④ 唔好郁 kube-system 嘅現有元件，除非題目明講。⑤ 作答喺題目指定嘅 namespace 入面，唔好開新 namespace 亂擺。唔熟字眼即刻查 詞彙表。
