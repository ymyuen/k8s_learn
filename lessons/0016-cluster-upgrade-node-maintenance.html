CKA 第十六課 · 升級唔斷線

Lesson 0016：叢集升級與節點保養（Killercoda）

目標：用 kubeadm upgrade 將小版號推上去，再用 cordon／drain／uncordon 等節點安心落場保養。升級係 CKA 高頻實作題——次序、指令、旗標全部要熟到變反射！

💡 點解呢課咁重要？
0015 將個叢集起咗出嚟，呢課等佢「大個仔＋做保養」。CKA 最鍾意考升級：邊個先邊個後、一次升幾多、drain 要加咩旗，錯一步就成題瀨嘢。喺 Killercoda 拋棄式 VM 度練到熟，入考場先唔會手震！
開場：先準備個「等升級」嘅叢集

沿用 0015 嘅 Killercoda 場景（如果 VM 已重置、要照 0015 重建：先 apt-cache madison kubeadm 查版本，再 sudo apt-get install -y kubeadm=1.34.x-1.1 kubelet=1.34.x-1.1 kubectl=1.34.x-1.1 將三件套釘喺 1.34 之後先 init——直接 init 會拎到 repo 最新版，就冇得升喇）。本課假設有一部 control-plane 同一部 worker、Kubernetes 1.34.x，要升去 1.35.x。

1. 睇下先：升級嘅核心規則

  • 一次只升一個小版號（1.34 → 1.35），唔准跳版（1.33 → 1.35 唔得）。
  • 先 control plane、後 worker；同一個 control-plane 群都要逐部嚟。
  • 每部節點內部次序固定：先升 kubeadm、再套用（upgrade apply/node）、最後升 kubelet＋kubectl 並重啟 kubelet。
  • kubeadm 升級嗰陣預設會自動 renew 憑證（都可以用 --certificate-renewal=false 閂咗佢）。

升級工具分三層，唔好撈亂：kubeadm 管「控制平面靜態元件同設定」，kubelet 係每部節點嘅執行者，kubectl 係客戶端——三者版本各自獨立升級。

2. 節點保養三指令

指令做咩Pod 會點
cordon 將節點標成唔收得新嘢（SchedulingDisabled） 唔再排新 Pod；跑緊嘅唔郁
drain cordon + 將上面啲 Pod 趕走（evict）去別嘅節點 趕得走嘅 Pod 被安全搬屋；DaemonSet 例外
uncordon 解返個標記，等節點恢復收 Pod 之後新 Pod 又排得入嚟
🏨 港式比喻：酒店翻新唔趕客
成間酒店 Full House 爆滿都要逐層翻新：drain＝幫客人搬房（Pod 由 Worker-A 搬去隔籬房，間吉房先開工升級）； cordon 只係門口掛「暫停入住」，房入面啲客唔郁；DaemonSet 好似駐場保安——唔搬（--ignore-daemonsets 就係話「保安留低」）； 整完 uncordon 拆牌，重新接客。

⬆️ 升級時間線：Worker-A 搬房＋CP 四步圈

個次序就係咁：control-plane 升完，先到 worker 落場。調轉嚟做，考官即刻畀你零分。

apt 升級 checklist（跟住剔，唔會漏）
☐ 1. unhold 解鎖：sudo apt-mark unhold kubeadm kubelet kubectl
☐ 2. madison 抄版：apt-cache madison kubeadm | head（copy 1.35.x-1.1 全串，唔好自己估）
☐ 3. install kubeadm：sudo apt-get install -y kubeadm=1.35.x-1.1
☐ 4. plan 睇路徑：sudo kubeadm upgrade plan
☐ 5a. CP 專用 apply：sudo kubeadm upgrade apply v1.35.x
☐ 5b. Worker 專用 node：sudo kubeadm upgrade node（唔係 apply！）
☐ 6. kubelet＋重啟：install kubelet/kubectl → daemon-reload → restart kubelet
☐ 7. hold 返鎖住：sudo apt-mark hold kubeadm kubelet kubectl
記：apply 換「控制平面爐頭」（static manifests），node 只更新「工人設定檔」——worker 跑 apply 會出事！

3. 實作 A：升級 control plane

喺 control-plane 上：先將 kubeadm 換去目標版本
# 1. Ubuntu 套件管理：kubeadm/kubelet/kubectl 通常被 apt-mark hold 鎖住，先解鎖
sudo apt-mark unhold kubeadm kubelet kubectl

# 2. 查倉庫有咩可用版本（記低 1.35.x 嘅正確 x，下面帶入）
apt-cache madison kubeadm | head -n 10

# 3. 升級 kubeadm（將 1.35.x 換成你查到嘅版號）
sudo apt-get update
sudo apt-get install -y kubeadm=1.35.x-1.1
kubeadm version
升級前檢查 + 套用
# 4. upgrade plan：列出可升級路徑同版本差異（先睇再郁手）
sudo kubeadm upgrade plan

# 5. 喺「第一部」control-plane 套用升級（只喺一部 cp 跑 apply）
sudo kubeadm upgrade apply v1.35.x
#    佢會逐個更新 kube-apiserver／controller-manager／scheduler 嘅 static manifest，
#    完成嗰陣印出 "Upgrade complete!"
升級 kubelet 同 kubectl，重啟 kubelet
# 6. kubeadm 只管控制平面 manifest；節點上嘅 kubelet 要自己換
sudo apt-get install -y kubelet=1.35.x-1.1 kubectl=1.35.x-1.1
sudo systemctl daemon-reload
sudo systemctl restart kubelet

# 7. 將版本鎖返（費事下次 apt 自動郁佢）
sudo apt-mark hold kubeadm kubelet kubectl

# 8. 驗收：control-plane 節點 VERSION 顯示 1.35.x
kubectl get nodes
唔熟嘅坑：apt 版號要帶後綴

Debian/Ubuntu 嘅套件版號係 1.35.x-1.1（後面多段 Debian revision）。apt-cache madison kubeadm 印出嚟嗰串就係正確寫法——直接 copy & paste，唔好自己估。一次只升一個小版，亦唔好將 upgrade apply 嘅目標寫成「最新」——考試題目會指明精確版號。

4. 實作 B：worker 升級（drain → 升 → uncordon）

喺 control-plane 上：先叫 worker 交出啲 Pod
# 9. drain：cordon（唔再排新嘅）+ 將舊有 Pod 安全趕走
#    <worker-node> = 你部 worker 節點名（先 get nodes 確認，Killercoda 成日叫 node01）
#    --ignore-daemonsets：DaemonSet 嘅 Pod 唔趕（佢哋本來就唔應該被搬走）
kubectl get nodes
kubectl drain <worker-node> --ignore-daemonsets
#    輸出列出被 evict 嘅 Pod；完嗰陣節點標成 Ready,SchedulingDisabled
喺 worker 上：升 kubeadm → node → kubelet
# 10. worker 端嘅 kubeadm 升級（唔使 upgrade apply——嗰個係 cp 嘅事）
sudo apt-mark unhold kubeadm kubelet kubectl
sudo apt-get update
sudo apt-get install -y kubeadm=1.35.x-1.1

# 11. kubeadm upgrade node：更新 worker 上嘅 kubelet 設定
sudo kubeadm upgrade node

# 12. 換 kubelet/kubectl 並重啟 kubelet
sudo apt-get install -y kubelet=1.35.x-1.1 kubectl=1.35.x-1.1
sudo systemctl daemon-reload
sudo systemctl restart kubelet
sudo apt-mark hold kubeadm kubelet kubectl
返 control-plane：uncordon 放行
# 13. 解除唔收得嘢，等 worker 恢復收 Pod
kubectl uncordon <worker-node>
kubectl get nodes
#    兩部都顯示 1.35.x，worker 嘅 STATUS 唔再有 SchedulingDisabled

# 14. 驗收：佈 3 粒 Pod 確認 worker 又接到嘢做
kubectl create deployment post-upgrade --image=nginx:1.25 --replicas=3
kubectl get pods -o wide
kubectl delete deployment post-upgrade
你應該觀察到咩

第 9–13 步係節點保養嘅完整節奏：drain 將 Pod 安全搬走（cordon 只係「唔再排新嘅」）→ 喺吉咗嘅節點上升級 → uncordon 等佢重新開工。升級 worker 期間你啲 service 冇斷線——因為 Pod 一早喺別嘅節點繼續跑。呢個就係 drain 存在嘅意義。

5. 實作 C：憑證檢查同 kubeconfig

憑證到期檢查
# 15. kubeadm 簽嘅憑證有時效；check 下仲剩幾耐到期
sudo kubeadm certs check-expiration
#    表格列出各憑證嘅 RESIDUAL TIME（例如 apiserver 一年、admin.conf 一年）

# 16. 快到期就手動續約（kubeadm 都會喺 upgrade 嗰陣自動 renew）
sudo kubeadm certs renew all
sudo kubeadm certs check-expiration
kubeconfig 嘅角色分工
# 17. /etc/kubernetes 下面嘅 kubeconfig 各自代表一個角色
ls /etc/kubernetes/*.conf
kubectl config view
#    admin.conf   → 叢集管理員（kubectl 用嗰份）
#    controller-manager.conf → controller-manager 用自己身份連 apiserver
#    scheduler.conf          → scheduler 嘅身份
#    kubelet.conf            → 每部節點 kubelet 嘅身份
收尾（Killercoda VM 直接閂咗就得）
# 18. 本課喺拋棄式 VM 進行——練完直接閂場景，本機叢集唔受影響
kubectl get nodes
考場小抄

① 升級口訣：cp 先 node 後、一次一小版；每部內「kubeadm → apply/node → kubelet」。 ② 指令五連：apt install kubeadm=版本 → kubeadm upgrade plan → kubeadm upgrade apply vX.Y.Z（cp）／kubeadm upgrade node（worker）→ apt install kubelet=版本 kubectl=版本 → systemctl restart kubelet。③ drain 必帶 --ignore-daemonsets；卡住嗰陣睇 error 訊息決定加唔加 --delete-emptydir-data 或 --force（題目有 emptyDir Pod 嗰陣）。④ cordon 唔搬屋、drain 搬屋、uncordon 復工。⑤ 憑證：kubeadm certs check-expiration／renew all；upgrade 預設自動 renew。⑥ kubeconfig：admin.conf 係管理員嗰把，/etc/kubernetes/*.conf 各角色一把。

本課戰果

  • 你用 kubeadm upgrade plan/apply 將 control plane 升咗一個小版，仲升級埋 kubelet/kubectl。
  • 你用 drain → 升級 → uncordon 完成 worker 嘅無痛升級。
  • 你識分 cordon／drain／uncordon 嘅差別同旗標。
  • 你 check 咗憑證到期時間，識認 /etc/kubernetes 各 kubeconfig 嘅角色。
