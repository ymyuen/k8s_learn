Lesson 0003：Labels & Selectors 認人機制

目標：上一課你知 Deployment 靠 selector 認領 ReplicaSet，ReplicaSet 靠 selector 認領 Pod。今課就係要搞掂呢套「認人機制」——控制器唔係靠個名認親，係靠 Label 同 Selector 認人，仲要親手整隻孤兒 Pod 再救返佢。

💡 點解要學 Labels？
CKA 最常見嘅瀨嘢現場就係「Pod 數量對唔上、有粒 Pod 冇人理」。十居其九都係 selector 同 label 唔夾。識睇 --show-labels 同 -l

🔖 Selector 認人圖：邊個管邊個

睇下幅圖就明：RS 只認 app=nginx，你一改 label，舊 Pod 即刻變孤兒，RS 仲會補多粒湊返夠數。

🎞️ 四格漫畫：改一粒 label，Pod 由 3 變 4 再返 3

連戲咁睇：改走一粒 → RS 覺得唔夠數即補 → 全場變 4 粒 → 改返好 → RS 見多咗即斬 → 返 3 粒。RS 從來唔斬孤兒，佢只係識「唔夠就補、多咗就斬」。

1. Label：物件嘅身份證

Label 就係黐喺物件上面嘅鍵值對（key=value），用途得兩個字：組織同選取。鍵名規則要記：可以加 prefix（例如 app.kubernetes.io/name，prefix 要係 DNS 子域名）；名同值最多 63 字、只可以用字母數字加 - _ .，頭尾一定要係字母數字。最常用嘅鍵：app（咩應用）、tier（frontend/backend）、version（版本）。想查術語可睇 詞彙表。

畀邊個用改咗斷唔斷領養範例
Label（標籤）畀 selector 同 -l 用嚟認人、過濾會斷：Pod 個 label 一唔夾 selector 即變孤兒，RS 仲會補粒app=nginx、tier=frontend
Annotation（註解）畀人睇、畀工具睇（說明、change-cause）唔斷：改幾多都唔影響認領，selector 睬你都傻kubernetes.io/change-cause="更新到 1.26"
Name（名）畀人同 kubectl get/delete 名 直接點名用唔斷領養但改唔到：控制器唔靠名認人，名一開好就定死nginx-7c9d8b9f6-abc12（Pod 名，刪咗就冇）

記住呢句就搞掂：Label 係畀 selector 揀嘅，Annotation 係畀人睇嘅。

2. Selector 兩種寫法

Selector 就係「認人條件」。每個控制器都將條件寫喺 selector 入面，用 , 駁埋一齊就要全部符合先算認領。有兩種寫法：

型別運算子範例意義
Equality-based
（等值式）		=、==app=nginx該 label 的值等於 nginx
!=tier!=frontend值不等於 frontend（或沒有該鍵）
Set-based
（集合式）		inapp in (nginx, busybox)值是集合中的其中一員
notintier notin (frontend, backend)值不在集合中
existstier（有鍵）、!tier（沒鍵）只看鍵存不存在，不看值
kubectl 帶 selector 的三種寫法（-l）
# equality：等於
kubectl get pods -l app=nginx

# set-based：值在集合內（留意括號是 ( )，不是 { }）
kubectl get pods -l 'app in (nginx, busybox)'

# set-based exists：只要沒有 tier 這個鍵
kubectl get pods -l '!tier'
🐚 點解 set-based 要加單引號？（shell quoting 一分鐘）

個 shell 見到括號同空格會自己解讀，所以 'app in (nginx)' 一定要用單引號包住成串先至原粒送畀 kubectl：唔包，bash 會當括號係 subshell 而彈錯；用雙引號喺 bash 都得，但單引號最穩陣（Windows PowerShell 都係單引號）。記住：有括號、有空格、有 ! 就加單引號。

想一次過要幾個條件同時成立（AND），用逗號駁：kubectl get pods -l 'app in (nginx, busybox),tier=frontend' ＝ app 係 nginx 或 busybox 而且 tier 等於 frontend。逗號前後唔好加空格，照抄呢個 pattern 就得。

3. 實作 A：動手玩 Label

喺你個 kind 叢集開個新 terminal 照打。如果 0002 結尾唔記得清理，先 kubectl delete deployment nginx 執返乾淨：

建立 Deployment，然後動手改 label
# 1. 建立 3 顆副本的 Deployment——它就是我們認人實驗的主角
kubectl create deployment nginx --image=nginx:1.25 --replicas=3
kubectl rollout status deployment/nginx   # 等 3 顆都就緒

# 2. 把 label 一起印出來
kubectl get pods --show-labels
#    每顆 Pod 應該有兩個 label：app=nginx（Deployment 加的）與
#    pod-template-hash=...（ReplicaSet 加的，用來區分新舊版本）

# 3. 依 label 過濾：只要 app=nginx 的 Pod
kubectl get pods -l app=nginx

# 4. 挑一顆，幫它加 label tier=frontend（鍵不存在，直接加）
kubectl label pod nginx-(隨機尾碼) tier=frontend

# 5. 用新 label 也找得到它
kubectl get pods -l tier=frontend

# 6. 移除 label：鍵名尾巴加減號 -
kubectl label pod nginx-(隨機尾碼) tier-

# 7. Set-based 示範：值「在集合內」才選中
kubectl get pods -l 'app in (nginx)'
你應該觀察到咩

--show-labels 會多印一欄 LABELS；-l 按條件過濾，列出嘅 Pod 數量會跟住條件變。將 tier=frontend 加落其中一粒，kubectl get pods -l tier=frontend 就只會見到嗰粒；刪走 label 之後再查就搵唔返。

4. 實作 B：整隻孤兒出嚟（selector 唔夾）

CKA 成日考：「有粒 Pod 冇人理」。新手會諗：不如直接寫份 selector.matchLabels 同 template labels 唔夾嘅 ReplicaSet YAML 睇下咩事——唔得，apiserver 會直接彈你（selector does not match template labels）。現實世界嘅「唔夾」多數係手多多改咗 label搞出嚟：Pod 個 label 一變，控制器即刻唔認佢。繼續用實作 A 個叢集：

改掉一顆 Pod 的 label，製造孤兒
# 8. 先確認現在 3 顆 Pod 都掛著 app=nginx
kubectl get pods --show-labels

# 9. 挑一顆，把它的 app 值改成 scratch。
#    注意：app 鍵已存在，改值要加 --overwrite
kubectl label pod nginx-(隨機尾碼) app=scratch --overwrite

# 10. 再看一次：Pod 變成 4 顆！
#     新尾碼的那顆是 RS 補的（它只認 app=nginx，少了就補）；
#     舊的那顆還 Running，但 label 已不合——它成了孤兒
kubectl get pods --show-labels

# 11. 用 selector 分邊：誰是 RS 管的、誰是孤兒
kubectl get pods -l app=nginx      # 3 顆，RS 管的
kubectl get pods -l app=scratch     # 1 顆，孤兒

# 12. 看 RS 的認人條件（SELECTOR 欄）
kubectl get rs -o wide
kubectl describe rs (RS 名稱)
#    SELECTOR 是 app=nginx,pod-template-hash=... 兩條件都得符合

# 13. 修復：把孤兒的 app 改回 nginx。
#     RS 一看到符合條件的 Pod 變 4 顆，立刻砍掉多出來的一顆
kubectl label pod (孤兒 Pod 名稱) app=nginx --overwrite
kubectl get pods --show-labels   # 回到 3 顆

# 14. 收尾：刪 Deployment（它的 ReplicaSet 一起刪）
#     （不想修復也可直接刪孤兒：kubectl delete pod (孤兒名稱)）
kubectl delete deployment nginx
你應該觀察到咩

第 10 步重點係「變咗 4 粒」：RS 唔會斬走嗰粒改咗 label 嘅 Pod（只係唔再認佢），反而會補多粒湊返 3 粒期望數。舊嗰粒又 Running 又冇人管——呢啲就叫孤兒（orphan）。判讀流程：kubectl get rs -o wide 對 SELECTOR 欄，再對 kubectl get pods --show-labels，最後 kubectl describe rs (RS 名稱) 確認。

考場小抄

三個必背旗標要背到滾瓜爛熟：--show-labels（印埋 label）、-l 'selector'（按條件過濾）、-L key（大寫，直接加多欄，例如 kubectl get pods -L app）。改已有 label 要加 --overwrite；刪 label 用 key-。一見「Pod 數唔啱」或者「有粒 Pod 冇人理」，第一時間對 selector 同 labels，唔好估估下。

本課戰果

  • 你識寫 equality-based 同 set-based 嘅 selector，仲識用 -l 過濾。
  • 你識用 kubectl label 加 label、改值（--overwrite）、刪走（key-）。
  • 你識斷症「selector 唔夾 → Pod 變孤兒」，仲識救返佢。
