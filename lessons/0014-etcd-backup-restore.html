Lesson 0014：etcd 備份與還原

目標：親手對「仲生勾勾嘅 etcd」做 snapshot save、用 snapshot status 驗貨，再預演 snapshot restore。搞掂呢套，考試話要還原你唔會手震！

💡 點解呢課咁重要？
etcd 係成個叢集嘅記憶——Deployment、Secret、Namespace 全部瞓喺入面。etcd 瓜咗等如失憶，CKA 實考「備份還原」成套：存、驗、還原，唔識就真係瀨嘢！

1. 睇下先：snapshot 係咩、restore 做緊咩

  • snapshot save：將成個 etcd 數據庫（連 member 狀態）倒成單一檔案。對住「仲生緊嘅 etcd」直接存就得，唔使停機。
  • snapshot status：讀個 snapshot 檔印出 metadata（revision、總 key 數、db 大細）——備份完「驗到係好嘅」先算數。
  • snapshot restore：將個 snapshot 檔「解壓」成一個全新嘅數據目錄。留意——佢唔係原地復活舊目錄，而係起個新 member 文件夾，再駁返畀 etcd 用。所以還原本質係：新數據目錄駁返 + 重啟 etcd。

考試必背路徑：etcd 係 static pod，manifest 喺 /etc/kubernetes/manifests/etcd.yaml，數據目錄喺 /var/lib/etcd。憑證三件套固定擺喺 /etc/kubernetes/pki/etcd/：ca.crt（CA）、server.crt／server.key（etcd 自己）。

三條指令模板（背到爛）
# 存
ETCDCTL_API=3 etcdctl --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key \
  snapshot save /backup/etcd-snapshot.db

# 驗
ETCDCTL_API=3 etcdctl snapshot status /backup/etcd-snapshot.db --write-out=table

# 還原（起個新數據目錄 /var/lib/etcd-from-backup）
ETCDCTL_API=3 etcdctl snapshot restore /backup/etcd-snapshot.db \
  --data-dir=/var/lib/etcd-from-backup
環境提醒：ETCDCTL_API=3

etcdctl 對 v3 API 有歷史包袱，考試慣例喺指令前加 ETCDCTL_API=3 確保行 v3。加咗無害、漏咗可能中伏——照抄就啱。endpoints 一律 https://127.0.0.1:2379（本機 etcd 就聽呢度）。

📱 港式比喻：電話 iCloud 備份
snapshot save 就係撳「立即備份」上 iCloud；之後新裝嘅 App（t1 起嘅 Deployment）唔會入返舊備份； snapshot restore 等於買部新機倒嘢——唔係整返舊機，而係開個新殼（新數據目錄）再倒返舊資料，倒完之後裝嘅嘢全部唔見。

💾 etcd 備份還原手術圖：五格漫畫

記住個節奏：存 → 驗 → 還原出新目錄 → 換目錄重啟。restore 從來唔係「整返舊嗰個」，而係「換個新嘅上嚟」。

憑證／參數係咩港式記法
ca.crt簽發晒所有 etcd 憑證嘅 CA👩 阿媽：認人靠佢個印
server.crt／server.keyetcd 自己出示嘅身份證＋鎖匙🪪 我係邊個：保安要睇你證件
--endpoints=https://127.0.0.1:2379本機 etcd 聽嘅位🏠 門牌：唔寫就搵唔到門口
ETCDCTL_API=3強制行 v3 API🗣️ 講新話：唔加可能雞同鴨講
本機 kind（實作 A）Killercoda VM（實作 B／考試）
etcd 喺邊節點容器入面嘅 static pod（etcd-kind-control-plane）VM 本機嘅 static pod（etcd-<hostname>）
etcdctl 點行kubectl exec … -- sh -c '…' 包住行VM 上直接行（若無 etcdctl 就一樣用 exec 包）
練到邊save＋status＋restore 去 /tmp（唔郁真數據）成套換目錄手術（搬 yaml → 換腦 → 搬返）

2. 實作 A：喺本機 kind 叢集存一份 snapshot

kind 嘅 etcd 係跑喺 control-plane 節點上嘅 static pod（個名叫 etcd-kind-control-plane）。我哋喺 pod 入面行 etcdctl，再將個檔拷出嚟。先整啲「值得備份嘅狀態」：

先做啲嘢，等 snapshot 有內容
# 1. 求其起個 namespace 當「要被備份嘅狀態」
kubectl create ns backup-me
kubectl create deployment hello-backup --image=nginx:1.25 --replicas=2
kubectl rollout status deployment/hello-backup
搵到 etcd pod，執行 snapshot save
# 2. etcd static pod 嘅名 = etcd-<節點名>
kubectl get pods -n kube-system | grep etcd
#    etcd-kind-control-plane

# 3. 喺 pod 內執行 etcdctl snapshot save（三憑證 + 本機端點）
#    檔案要寫入 /var/lib/etcd（呢個係 hostPath，節點容器先讀到、docker cp 先拷得出）
kubectl exec -n kube-system etcd-kind-control-plane -- sh -c 'ETCDCTL_API=3 etcdctl --endpoints=https://127.0.0.1:2379 --cacert=/etc/kubernetes/pki/etcd/ca.crt --cert=/etc/kubernetes/pki/etcd/server.crt --key=/etc/kubernetes/pki/etcd/server.key snapshot save /var/lib/etcd/etcd-snapshot.db'
#    成功會印 "Snapshot saved at /var/lib/etcd/etcd-snapshot.db"

# 4. 確認檔案存在同大細
kubectl exec -n kube-system etcd-kind-control-plane -- ls -lh /var/lib/etcd/etcd-snapshot.db
拷去 host、用 snapshot status 驗證
# 5. 由節點容器拷返 WSL2 host（docker 對 kind 節點直接用；路徑喺 hostPath 入面先拷到）
docker cp kind-control-plane:/var/lib/etcd/etcd-snapshot.db ./etcd-snapshot.db
ls -lh etcd-snapshot.db

# 6. 喺 pod 內驗證 snapshot 讀到（存完一定要驗——爛檔冇人想還原嗰陣先發現）
kubectl exec -n kube-system etcd-kind-control-plane -- sh -c 'ETCDCTL_API=3 etcdctl snapshot status /var/lib/etcd/etcd-snapshot.db --write-out=table'
#    table 會印 HASH / REVISION / TOTAL KEYS / TOTAL SIZE
預演 restore：還原去一個暫存目錄（唔郁正式數據）
# 7. 將 snapshot 還原成「新數據目錄」去 /tmp——證明呢份備份還原得到
kubectl exec -n kube-system etcd-kind-control-plane -- sh -c 'ETCDCTL_API=3 etcdctl snapshot restore /var/lib/etcd/etcd-snapshot.db --data-dir=/tmp/restored-etcd'
#    成功會印 "Restored a new etcd database..."

# 8. 睇下還原出嚟嘅目錄結構（member/ 就係 etcd 嘅文件夾）
kubectl exec -n kube-system etcd-kind-control-plane -- ls /tmp/restored-etcd
kubectl exec -n kube-system etcd-kind-control-plane -- ls /tmp/restored-etcd/member

# 9. 收走暫存同 snapshot（備份檔 host 上留返）
kubectl exec -n kube-system etcd-kind-control-plane -- rm -rf /tmp/restored-etcd /var/lib/etcd/etcd-snapshot.db
kubectl delete ns backup-me
kubectl delete deployment hello-backup
你應該觀察到咩

第 6 步嘅 table 係「備份品質保證」：REVISION 代表 etcd 寫到邊一版、TOTAL KEYS 係 key 總數。第 7–8 步先睇明 restore 本質：佢將 snapshot「吐」成一個新嘅數據目錄（含 member 子目錄），唔會郁你跑緊嘅 etcd。真正切換只係將 etcd 指去新目錄再重啟——下面實作 B 就係嗰台手術。

3. 實作 B：完整還原手術（喺 Killercoda VM 上演練）

本機 kind 嘅 etcd 同正式叢集生得唔同（manifest、kubelet 都喺節點容器入面），真正嘅還原手術要喺VM 型叢集上做先有意思——考試環境都係 VM。開個 Killercoda 嘅 kubeadm／多節點場景，將下面成套跑一次（約 15 分鐘）。

完整還原流程（VM 版；只可意會不可省略）
# step 0 — 開 Killercoda（killercoda.com），揀個「kubeadm、含 control-plane」嘅場景
#    下面假設你喺嗰部 VM 嘅 root／sudo 環境

# step 1 — （第一次練習先）存一份而家狀態嘅備份
#    若 VM 嘅 host 冇裝 etcdctl（kubeadm 唔保證會裝）：將下面每行 etcdctl
#    包成 kubectl -n kube-system exec -it etcd-$(hostname) -- sh -c '…' 喺 pod 內跑，
#    憑證路徑同指令內容完全一樣——本課實作 A 就係咁做
ETCDCTL_API=3 etcdctl --endpoints=https://127.0.0.1:2379 --cacert=/etc/kubernetes/pki/etcd/ca.crt --cert=/etc/kubernetes/pki/etcd/server.crt --key=/etc/kubernetes/pki/etcd/server.key snapshot save /root/etcd-snapshot.db
ETCDCTL_API=3 etcdctl snapshot status /root/etcd-snapshot.db --write-out=table

# step 2 — 還原成新數據目錄（唔好擺喺舊嘅 /var/lib/etcd 上）
ETCDCTL_API=3 etcdctl snapshot restore /root/etcd-snapshot.db --data-dir=/var/lib/etcd-from-backup

# step 3 — 停咗 etcd static pod：將 manifest 搬走，kubelet 就會收走 etcd
mv /etc/kubernetes/manifests/etcd.yaml /root/
crictl ps | grep etcd || docker ps | grep etcd
#    等到輸出睇唔到 etcd 容器為止（kubelet 幾秒內收走）

# step 4 — 備份舊數據目錄、將還原出嚟嘅換上去
mv /var/lib/etcd /var/lib/etcd.bak
mv /var/lib/etcd-from-backup /var/lib/etcd

# step 5 — 放返 manifest，等 kubelet 重新拉起 etcd（呢刻佢讀嘅係新數據目錄）
mv /root/etcd.yaml /etc/kubernetes/manifests/
crictl ps | grep etcd
sleep 10
kubectl get nodes
kubectl get pods -A
#    節點 Ready、控制平面元件返嚟，即係還原成功
還原後一定會唔見咗啲狀態——呢個唔係 bug

還原即係返去 snapshot 嗰一刻：snapshot 之後先起嘅物件全部消失（step 1 存檔之後嘅操作都會唔見）。呢個正正係備份嘅意思：時間點 = 還原點。另外 restore 會換咗 etcd 嘅 member ID，所以「將還原後嘅節點重新加入叢集」喺 HA 環境要小心——考試只考單一 control-plane 或者跟題目指令行就得。

考場小抄

① 三指令：snapshot save（三憑證+endpoints 模板）／snapshot status（驗）／snapshot restore --data-dir=...（還原成新目錄）。② 必背路徑：/etc/kubernetes/manifests/etcd.yaml、/var/lib/etcd、憑證喺 /etc/kubernetes/pki/etcd/。③ restore 係「新數據目錄駁返」唔係原地復活——先停 static pod（搬 manifest）、換目錄、再放返 manifest。④ 還原點＝snapshot 時間點，之後嘅狀態會消失。⑤ 題目若畀 member 多嘅叢集，restore 通常只對單一 member 做、再將其他 member 清走重建。⑥ 指令前 ETCDCTL_API=3 照抄。

本課戰果

  • 你喺本機 kind 叢集對「生緊嘅 etcd」做咗 snapshot save，仲用 snapshot status 驗過。
  • 你將備份檔拷出節點，仲預演 restore（還原去暫存目錄）證明還原到。
  • 你明晒完整還原手術每一步，識得喺 Killercoda VM 上照表操課。
