CKA 第一課 · 大腦同手腳

Lesson 0001：叢集架構與你嘅第一個 Pod

目標：用香港職場比喻＋架構圖解搞清 Control Plane 同 Worker Node 分工，再親手用 kind 起個真叢集、跑出第一粒 Pod。考 CKA 排錯嗰陣，一眼睇穿邊個組件瀨嘢！

💡 點解呢課咁重要？
好多人淨係死背 kubectl run，一入考場見到 Worker Node NotReady 或者 Pod 永遠 Pending 就企咗喺度。搞掂呢個血脈圖，你先識得排錯！

1. 點解要「成班機器」？

你已經識 docker run：單機拉 image、跑 process，搞掂。但單機有三面牆，Kubernetes 生嚟就係拆牆嘅：

  • 故障：部機瓜咗，個 app 就跟住瓜。K8S 會喺第二部機重新拉起 Pod。
  • 伸縮：流量爆煲，單機塞唔落。K8S 話到畀新 Pod 知應該瞓邊張床。
  • 管理：幾十部機逐部 ssh 入去開 container？K8S 畀個單一 API 你統一管。

一句記住：K8S 將「跑容器」由「一部機」搬到「一班機」，仲要令呢班機睇落似一部。

2. 概念圖解：成個 Kubernetes 就係一間大公司

🏢 職場擬人化對照架構圖

🔢 一筆請求嘅編號旅程：邊個行先、邊個唔掂邊個

背法：①你 → ②秘書 → ③賬本 → ④HR揀床位 → ⑤賬本寫死邊張床 → ⑥大工頭認領 → ⑦工人開工 → 報返上去。HR（scheduler）唔會 WhatsApp 大工頭（kubelet），大工頭亦唔會自己去揭賬本（etcd）。

角色喺邊跑元件一句話職責
Control Plane
（大腦）		 控制平面節點 kube-apiserver 對外唯一 API 入口，所有指令都經呢度入
etcd 鍵值資料庫，存放叢集所有狀態（CKA 必考備份）
kube-scheduler、kube-controller-manager 排程器揀 Node；控制器將現況推向期望狀態
Worker Node
（手腳）		 工作節點 kubelet、kube-proxy、Container Runtime kubelet 保證容器照規格跑；kube-proxy 實作 Service 網路規則

關鍵心法：你（經 kubectl）永遠只同 kube-apiserver 傾偈。apiserver 驗完你身份，將期望狀態寫入 etcd，其他元件睇住 etcd 各自開工。呢個叫「宣告式」（declarative）：你宣告「我要 3 個 nginx」，排程、啟動、自癒唔使你理。

一筆請求嘅生命旅程
你打 kubectl run nginx --image=nginx
→ kube-apiserver（驗證身份、寫入 etcd）
→ kube-scheduler（揀一粒 Node，寫返入 etcd）
→ 嗰粒 Node 嘅 kubelet（叫 container runtime 起容器）
→ 回報狀態畀 apiserver → 存返入 etcd
docker run（單機）kubectl run（成班機）
打指令畀邊個直接畀呢部機嘅 Docker daemon只畀 kube-apiserver，全叢集唯一入口
狀態記喺邊記喺呢部機自己（冇中央賬本）記喺 etcd，全公司唯一真理賬本
邊個揀機冇得揀，就係呢部機scheduler 幫你揀最 fit 嘅 Node
機死點機瓜＝app 跟住瓜，自己重開控制器見數唔啱，喺第二部機自動補返粒

一句記：docker run 係「你親手開一部機嘅一個 container」；kubectl run 係「你同秘書落單，成間公司幫你搵位、開工、包善後」。

3. 終端機實作：起叢集、跑第一粒 Pod

理論夠喇——郁手。我哋用 kind（Kubernetes in Docker）起個真叢集，唔使掂雲。

環境準備（只做一次）

你部 Mac 已有 brew 同 kind。補齊 kubectl 同容器運行時：brew install kubectl、brew install colima docker 後 colima start。跟住 kind --version、kubectl version --client 確認見到版號。

指令清單（照住打）
# 1. 起叢集（約 2 分鐘）。唔帶 config 係單節點——
#    嗰粒 Node 同時係 control-plane 兼 worker
kind create cluster --name cka-lab

# 2. 睇 Node——得 kind-control-plane 一粒，ROLE 係 control-plane
kubectl get nodes

# 3. 跑出第一粒 Pod
kubectl run nginx --image=nginx

# 4. 睇 Pod 狀態（等佢變 Running）
kubectl get pods
kubectl get pods -o wide

# 5. 睇細節——事件、IP、容器狀態喺晒度
kubectl describe pod nginx

# 6. 收工清理（留返乾淨場畀下一課）
kubectl delete pod nginx
你應該觀察到咩

get pods 嘅 READY 由 0/1 變 1/1、STATUS 由 ContainerCreating 變 Running。describe 碌到最底 Events 會寫低 Pull image → Started 嘅全過程——90% 排錯線索都匿喺呢度。

選配：真正嘅一主一從（雙節點）
# kind-config.yaml
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
nodes:
- role: control-plane
- role: worker

# 重新起（會洗走舊嘢，約 2 分鐘）
kind delete cluster --name cka-lab
kind create cluster --name cka-lab --config kind-config.yaml
kubectl get nodes   # 呢次有 kind-control-plane＋kind-worker 兩粒
課前預告：點解單節點都跑到 Pod？

諗下蘭桂坊門口保安咁：平時管理層樓層係 VIP 房，門口阿哥見你冇 VIP 卡就唔畀你入；而家你單機試玩，酒吧暫時人少，保安鬆手放你入去坐咗先。記住呢個怪現象，0005先解釋。

考場小抄

CKA 准查官方文件，但唔准嘥時間。練到「kubectl run／get／describe」變反射動作。縮寫記住：po（pods）、ns（namespaces）、no（nodes）。千祈唔好以為 etcd 會同 scheduler／kubelet 直接傾偈——全叢集得 apiserver 掂到 etcd。

本課戰果

  • 你講得出 control-plane 同 worker 嘅分工，同埋邊個揸住叢集狀態。
  • 你用 kind 起咗個真叢集，跑出、睇過、刪走第一粒 Pod。
