Helm、Kustomize、CRD 與 Operator

0015／0016 在 Killercoda 玩 kubeadm；本課回本機的 Calico 叢集（0012 之後一直留著）。主題是「怎麼把一整套應用交給叢集」：Helm（打包好的安裝包）、Kustomize（不用模板的宣告式疊加）、CRD／Custom Resource／Operator（讓叢集認識你自訂的物件）。最後把 CNI／CSI／CRI 三個介面收攏，Phase 4 就圓滿了。

三種「交付 YAML」的方式

HelmKustomize原生 YAML＋kubectl
本質 套件管理員（chart＝模板＋values） 宣告式「基底＋疊加」 一份份寫死的檔案
換環境 --set 或換 values 檔 換 overlay 目錄 複製一份改（最容易出錯）
回滾／卸載 helm rollback／uninstall 沒有 release 概念（靠 kubectl） 沒有（自己刪）
適合 安裝大型第三方套件（資料庫、監控） 自己維護的一組 YAML 要分環境 極簡、單一物件練習

一句話：Helm 管「套件與版本」，Kustomize 管「同一份 YAML 的環境差異」。

實作 A：Helm 安裝一套 nginx

在 WSL2 安裝 helm（官方安裝腳本，一次性）
# 1. 先確認叢集還在（0012–0014 的 Calico 雙節點；若不在，用 0012 的 kind-calico.yaml 重建）
kubectl get nodes

# 2. 下載並執行官方安裝腳本（get-helm-3）
curl -fsSL -o get_helm.sh https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3
chmod 700 get_helm.sh
./get_helm.sh
helm version
加 repo、搜尋、安裝
# 3. 加入 Bitnami 的 chart repo（Helm 的「軟體來源」）
#    Bitnami 現在也提供 OCI registry（oci://registry-1.docker.io/bitnamicharts），
#    本課用傳統 repo 教學；兩者指令語法略有不同
helm repo add bitnami https://charts.bitnami.com/bitnami
helm repo update

# 4. 搜尋 repo 裡的 chart；-l 列出全部版本，挑一個「釘版」安裝（--version）
helm search repo bitnami/nginx --versions | head -n 5
helm search repo bitnami/nginx

# 5. 安裝：release 名叫 myweb，chart 是 bitnami/nginx
#    （chart 會展開成 Deployment/Service/…一整組 YAML 送進叢集）
#    進版控的團隊會釘 chart 版本：helm install myweb bitnami/nginx --version <上一步看到的版號>
helm install myweb bitnami/nginx
helm list

# 6. 用 helm 的 label 看它到底建了哪些東西
kubectl get all -l app.kubernetes.io/instance=myweb
--set 覆寫、升級、回滾、卸載
# 7. 用 --set 覆寫 chart 的預設值（每個 chart 的 keys 以 helm show values 輸出為準）
helm show values bitnami/nginx | grep -A4 -i 'replicaCount\|service:'
helm upgrade myweb bitnami/nginx --set replicaCount=3
kubectl get pods -l app.kubernetes.io/instance=myweb
#    副本從 1 變 3

# 8. 看 release 的版本歷史
helm history myweb

# 9. 回滾到第一個版本（revision 1）——Helm 版的 rollout undo
helm rollback myweb 1
kubectl get pods -l app.kubernetes.io/instance=myweb

# 10. 卸載：把 chart 建出來的東西一次清光
helm uninstall myweb
helm list
你該觀察到什麼

Helm 的核心價值在第 10 步：一次卸載，全部清掉——所有由 chart 建立的物件都帶 app.kubernetes.io/instance=myweb，helm 依此回收。若某個 chart 的 --set 鍵名與這裡不同，helm show values bitnami/nginx 會印出完整的可設定清單——照它為準。

實作 B：Kustomize——基底與疊加

建立 base（基底）
# 11. 用 0004 的 dry-run 工作法產出 Deployment 與 Service，放進 kustom/base/
mkdir -p kustom/base kustom/overlays/prod
kubectl create deployment kustom-demo --image=nginx:1.25 --replicas=1 --dry-run=client -o yaml > kustom/base/deployment.yaml
kubectl create service clusterip kustom-demo --tcp=80:80 --dry-run=client -o yaml > kustom/base/service.yaml

# 12. base 的 kustomization.yaml：宣告「基底包含哪些檔」
nano kustom/base/kustomization.yaml
# 內容：
# apiVersion: kustomize.config.k8s.io/v1beta1
# kind: Kustomization
# resources:
# - deployment.yaml
# - service.yaml
預覽並套用 base
# 13. kubectl kustomize 直接印出合併後的完整 YAML（kustomize 的「dry-run」）
kubectl kustomize kustom/base | head -n 30

# 14. -k 就是「apply 這個 kustomization」
kubectl apply -k kustom/base
kubectl get deploy,svc kustom-demo
prod overlay：只疊加「副本數變 3」
# 15. overlay 的 kustomization.yaml：resources 指向 ../../base，再疊 patches
nano kustom/overlays/prod/kustomization.yaml
# 內容：
# apiVersion: kustomize.config.k8s.io/v1beta1
# kind: Kustomization
# resources:
# - ../../base
# replicas:
# - name: kustom-demo
#   count: 3

# 16. 預覽 prod 版：只有 replicas 那行被改成 3
kubectl kustomize kustom/overlays/prod | grep -E 'name:|replicas:'
kubectl apply -k kustom/overlays/prod
kubectl get deploy kustom-demo
#    DESIRED 變成 3——基底沒動，prod 疊加生效

# 17. 收尾
kubectl delete -k kustom/overlays/prod
rm -rf kustom
你該觀察到什麼

Kustomize 不寫模板、不改原檔：base 是一份「乾淨版」，overlay 只描述「差異」。第 16 步的 kubectl kustomize 是它的殺手鐧——先看合併結果再套用。CKA 愛考 -k（kustomization）與 -f（單一/多份 YAML）的分別。

實作 C：CRD、Custom Resource 與 Operator

Kubernetes 的 API 可以「長出新品種」：用 CRD（CustomResourceDefinition）定義一個新的資源型別，之後 kubectl apply 那種型別的物件——Custom Resource（自訂資源）。但注意：CR 被存進 etcd 之後，沒有 controller 的話它就只是「一筆資料」，不會有人照它的 spec 去建 Deployment。Operator 就是「會看某種 CR、把它變成實際資源」的控制器（0002 學的控制器模式，延伸到自訂資源）。

crd-widgets.yaml — 定義「Widget」型別
# crd-widgets.yaml — 宣告新資源型別：group example.com，kind Widget
apiVersion: apiextensions.k8s.io/v1
kind: CustomResourceDefinition
metadata:
  name: widgets.example.com
spec:
  group: example.com
  names:
    kind: Widget
    listKind: WidgetList
    plural: widgets
    singular: widget
  scope: Namespaced
  versions:
  - name: v1
    served: true
    storage: true
    schema:
      openAPIV3Schema:
        type: object
        properties:
          spec:
            type: object
            properties:
              replicas:
                type: integer
套用 CRD，認識新資源
# 18. 套用 CRD
nano crd-widgets.yaml
kubectl apply -f crd-widgets.yaml
kubectl get crd widgets.example.com

# 19. 從這一刻起，kubectl 認得 widgets 這個資源
kubectl api-resources | grep widgets
cr-widget.yaml — 建一個 Widget 實例
# cr-widget.yaml — apiVersion = <group>/<version>，kind = Widget
apiVersion: example.com/v1
kind: Widget
metadata:
  name: my-widget
spec:
  replicas: 3
套用、查詢、刪除
# 20. 套用 CR——apiserver 接受、存進 etcd
nano cr-widget.yaml
kubectl apply -f cr-widget.yaml
kubectl get widgets
kubectl get widget my-widget -o yaml
#    注意：沒有任何 Pod 被建出來——因為沒有 controller 在看 Widget

# 21. 收尾：刪 CR 與 CRD
kubectl delete -f cr-widget.yaml
kubectl delete -f crd-widgets.yaml
rm -f crd-widgets.yaml cr-widget.yaml get_helm.sh
kubectl get nodes
你該觀察到什麼

第 20 步是理解 Operator 的鑰匙：CR 只是資料，Controller 才是行為。真實世界的 Operator（如 prometheus-operator）會 watch「Prometheus 型 CR」，再幫你建出 Deployment、Service、RBAC 一整組。你等於在寫「自己的控制器」的邊界——把 CRD＋CR 這段練熟，就懂 Operator 在幹嘛了。

三個介面收攏：CNI、CSI、CRI

Kubernetes 用三個「標準介面」外掛底層實作，一路走來你都碰過：

介面管什麼本課程遇到的實作
CNIPod 網路（IP 與連通性）kindnet（0012 前）、Calico（0012 起）
CSI儲存（掛載磁碟）kind 內建 local-path（0008）
CRI容器執行時期containerd（kind／kubeadm 都用它）

口訣：CNI 管網、CSI 管存、CRI 管跑。

考場小抄

① Helm：repo add → install → upgrade --set → history／rollback → uninstall；release 是「一次安裝」的單位。② -k 吃 kustomization 目錄、-f 吃 YAML 檔；kubectl kustomize 目錄 可預覽。③ CRD 三步順序：先 apply CRD → 再 apply CR → 最後（若有的話）controller 才反應。④ CR 的 apiVersion 是「group/version」（example.com/v1），不是固定那幾個。⑤ 沒 controller 的 CR 只是一筆資料。⑥ 三介面口訣：CNI 網、CSI 存、CRI 跑。

本課戰果

  • 你在 WSL2 裝好 Helm，完成 install／--set 升級／rollback／uninstall 一整圈。
  • 你用 Kustomize 的 base＋overlay 達成「基底不動、prod 疊加」，並用 -k 套用。
  • 你寫出極簡 CRD 與 CR，親眼看到「沒有 controller 的 CR 只是資料」。
  • 你把 CNI／CSI／CRI 三介面收進同一張表。
