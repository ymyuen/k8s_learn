Phase 5 · 對應考綱：Troubleshooting（30%）＋全領域 · 需時約 60 分鐘

CKA 模擬考與衝刺策略

課程的最後一課：一場 60 分鐘、10 題的計時模擬考，涵蓋 0002–0019 的全部重點。考完對答案、錯題回課、再讀「一頁濃縮小抄」——之後你就有本事在真實考試（2 小時、可查官方文件、Killer.sh 17 題模擬）裡拿到好成績。報名流程不在本課範圍（MISSION 明訂 out of scope），我們練的是「應考能力」。

模擬考規則（先讀再開始）

① 計時 60 分鐘，10 題，每題約 6 分鐘。② 全程在 WSL2 bash、本機 Calico 叢集操作（第 8 題備份檔放 ~/practice）。③ 可查官方文件，但不能暫停查課文——先寫完再對答案。④ 每題下面附「驗收指令」，自己判斷過不過。⑤ 另開一個 ~/practice/mock-notes.txt 記「哪題卡住、卡在哪」。

實作 A：10 題計時模擬考

題 1（0002 複習）Deployment 更新與回滾
# 1. 需求：建 deployment web（nginx:1.25、3 副本）；更新成 nginx:1.26 並確認 rollout 成功；再回滾到上一版。
kubectl create deployment web --image=nginx:1.25 --replicas=3
kubectl set image deployment/web web=nginx:1.26
kubectl rollout status deployment/web
kubectl rollout undo deployment/web
#    驗收：kubectl rollout history deployment/web 有 ≥3 個 REVISION；get pods 3 顆 Running
題 2（0009 複習）把服務開成 NodePort
# 2. 需求：把題 1 的 deployment/web 暴露成 NodePort Service（port 80），確認 Endpoints 有 3 個 IP。
kubectl expose deployment web --type=NodePort --port=80 --name=web-np
#    驗收：kubectl get svc web-np（TYPE=NodePort）；kubectl get endpoints web-np 有 3 個 IP
題 3（0004 複習）Job 與 CronJob
# 3. 需求：a) 用 kubectl create job 建一支跑完即結束的 Job（busybox 印 hello）；b) 建立每 2 分鐘跑一次的 CronJob。
kubectl create job hello-job --image=busybox:1.36 -- echo hello-cka
kubectl create cronjob every-2min --image=busybox:1.36 --schedule="*/2 * * * *" -- date
#    驗收：a) get jobs → COMPLETIONS 1/1，kubectl logs job/hello-job 有 hello-cka
#          b) get cronjob 看到 SCHEDULE；等 2 分鐘 get jobs 出現 every-2min-xxx
題 4（0006 複習）ConfigMap 與 Secret 注入
# 4. 需求：a) configmap app-env（APP_ENV=staging）；b) secret db-secret（DB_PASSWORD=secret123）；
#            c) 一顆 pod 把兩者都掛成環境變數並印出。
kubectl create configmap app-env --from-literal=APP_ENV=staging
kubectl create secret generic db-secret --from-literal=DB_PASSWORD=secret123
kubectl run env-check --image=busybox:1.36 --restart=Never --dry-run=client -o yaml -- sleep 3600 > env-check.yaml
#    nano 手動加：envFrom.configMapRef（app-env）＋ env.valueFrom.secretKeyRef（DB_PASSWORD）
kubectl apply -f env-check.yaml
#    驗收：kubectl exec env-check -- sh -c 'echo $APP_ENV $DB_PASSWORD' → staging secret123
題 5（0013 複習）RBAC
# 5. 需求：namespace team-a 建 SA deployer；授權它在 team-a 內對 deployments 能
#           get/list/create/update；用 auth can-i 驗證 get=yes、delete=no、kube-system 的 get=no。
kubectl create ns team-a
kubectl -n team-a create serviceaccount deployer
kubectl -n team-a create role deployer-role --verb=get,list,create,update --resource=deployments
kubectl -n team-a create rolebinding deployer-bind --role=deployer-role --serviceaccount=team-a:deployer
#    驗收：三行 auth can-i（--as=system:serviceaccount:team-a:deployer）
題 6（0012 複習）NetworkPolicy
# 6. 需求：namespace app 內三顆 pod（app=a、app=b、app=x），app=b 跑 nginx。
#           NetworkPolicy：只准 app=a 連到 app=b 的 80，其餘全擋。
#           先建資源，再下 default-deny＋精準放行（0012 兩招）。
kubectl create ns app
kubectl -n app run app-b --image=nginx:1.25 --labels=app=b --restart=Never --port=80
kubectl -n app expose pod app-b --port=80
kubectl -n app run app-a --image=busybox:1.36 --labels=app=a --restart=Never -- sleep 3600
kubectl -n app run app-x --image=busybox:1.36 --labels=app=x --restart=Never -- sleep 3600
kubectl apply -f - <<'EOF'
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-a-to-b
  namespace: app
spec:
  podSelector:
    matchLabels:
      app: b
  policyTypes: ["Ingress"]
  ingress:
  - from:
    - podSelector:
        matchLabels:
          app: a
    ports:
    - protocol: TCP
      port: 80
EOF
#    驗收：exec app-a 連 http://app-b 通；exec app-x 連 http://app-b 逾時
題 7（0008 複習）靜態 PV + PVC
# 7. 需求：hostPath PV（kind-worker 的 /mnt/mock、1Gi、Retain、storageClassName ""）
#           + 同名的 PVC 綁定成功；掛進 pod 後能寫檔。
docker exec kind-worker mkdir -p /mnt/mock
kubectl apply -f - <<'EOF'
apiVersion: v1
kind: PersistentVolume
metadata:
  name: pv-mock
spec:
  capacity: {storage: 1Gi}
  accessModes: ["ReadWriteOnce"]
  persistentVolumeReclaimPolicy: Retain
  storageClassName: ""
  hostPath: {path: /mnt/mock, type: DirectoryOrCreate}
  nodeAffinity:
    required:
      nodeSelectorTerms:
      - matchExpressions:
        - key: kubernetes.io/hostname
          operator: In
          values: ["kind-worker"]
EOF
kubectl apply -f - <<'EOF'
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: pvc-mock
spec:
  accessModes: ["ReadWriteOnce"]
  storageClassName: ""
  resources: {requests: {storage: 1Gi}}
EOF
kubectl run pv-pod --image=busybox:1.36 --restart=Never --dry-run=client -o yaml -- sleep 3600 > pv-pod.yaml
#    nano 手動加 volume/volumeMount（claimName: pvc-mock，mountPath: /data）
kubectl apply -f pv-pod.yaml
#    驗收：get pvc → Bound；exec pv-pod 能寫能讀 /data/mock.txt
題 8（0014 複習）etcd snapshot
# 8. 需求：對本機 etcd 存 snapshot 到 /var/lib/etcd/etcd-mock.db、拷回 host，並用 snapshot status 驗證。
kubectl exec -n kube-system etcd-kind-control-plane -- sh -c 'ETCDCTL_API=3 etcdctl --endpoints=https://127.0.0.1:2379 --cacert=/etc/kubernetes/pki/etcd/ca.crt --cert=/etc/kubernetes/pki/etcd/server.crt --key=/etc/kubernetes/pki/etcd/server.key snapshot save /var/lib/etcd/etcd-mock.db'
docker cp kind-control-plane:/var/lib/etcd/etcd-mock.db ~/practice/etcd-mock.db
kubectl exec -n kube-system etcd-kind-control-plane -- sh -c 'ETCDCTL_API=3 etcdctl snapshot status /var/lib/etcd/etcd-mock.db --write-out=table'
#    驗收：status table 有 HASH/REVISION/TOTAL KEYS；host 上 ls -lh 看得到檔案
題 9（0016 複習）節點維護
# 9. 需求：把 kind-worker cordon，確認不可排程後再 uncordon 恢復。
kubectl cordon kind-worker
kubectl get nodes
kubectl uncordon kind-worker
kubectl get nodes
#    驗收：cordon 後 STATUS 出現 SchedulingDisabled；uncordon 後消失
題 10（0011 複習）Ingress 資源
# 10. 需求：寫一份 Ingress（ingressClassName: nginx）把 /demo 導到題 2 的 web-np:80。
#          本機 Calico 叢集沒有 ingress 控制器，本題練「寫對資源」——
#          apply 成功＋describe 無 schema 錯誤即算過（ADDRESS 留空屬預期）。
kubectl apply -f - <<'EOF'
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: mock-ingress
spec:
  ingressClassName: nginx
  rules:
  - http:
      paths:
      - path: /demo
        pathType: Prefix
        backend:
          service:
            name: web-np
            port:
              number: 80
EOF
#    驗收：kubectl get ingress mock-ingress 顯示規則；describe 無 error
模擬考收尾：清場＋計分

實作 C：考前 checklist（考前三天逐項打勾）

  • 文件書籤：把官方文件加進書籤並練過「在考試介面怎麼開」——kubectl Cheat Sheet、Deployment、Service、NetworkPolicy、PV、RBAC、etcd、kubeadm。真實考試可查官方文件，知道去哪找比背下來更省時。
  • 別名與環境：alias k=kubectl、export do="--dry-run=client -o yaml"、complete -F __start_kubectl k（bash completion）——考場第一分鐘先設好。
  • 加速反射：dry-run 產 YAML 再改（0004 起練到爛）、-o wide、kubectl explain 補欄位記憶。
  • 時間策略：先掃全部題目，先做有把握的；單題卡超過 5 分鐘就跳，最後再回來。
  • Killer.sh：購考附 2 次（各 36 小時），考前一至二週各做一次，錯題回到上面的對照表。

一頁濃縮小抄（考前十分鐘看這張）

全 20 課濃縮
# 四控制器口訣（0004）：
Deployment 補數量、DaemonSet 補節點、Job 補失敗、CronJob 補時間

# Workloads（0005–0007）：
requests 排程／limits 執行；QoS：全等=Guaranteed、全沒=BestEffort
taint 打節點、toleration 寫 Pod，效果 NoSchedule／PreferNoSchedule／NoExecute
liveness 失敗=重啟、readiness 失敗=摘流量；HPA 前提=metrics-server+requests

# Config & Storage（0006、0008）：
Secret base64 ≠ 加密；volume 掛載約 1 分鐘內同步、env 不更新
PVC 是請求、PV 是現貨、StorageClass 是工廠；RWO/ROX/RWX

# Networking（0009–0012）：
Service：selector→Endpoints→kube-proxy；NodePort 30000–32767
FQDN = svc.ns.svc.cluster.local；DNS 有回應 ≠ 後端可用
Ingress＝規則／IngressClass＝指名／Controller＝執行者
NetworkPolicy：規則出現即預設拒絕；podSelector{}＝全選；egress 別忘 DNS

# 叢集管理（0013–0017）：
RBAC：Role×RoleBinding=ns、ClusterRole×RoleBinding=限回 ns、
      ClusterRole×ClusterRoleBinding=全叢集；auth can-i 萬用
etcd：save→status→restore 三模板；路徑 /etc/kubernetes/manifests、/var/lib/etcd
升級：cp 先 node 後、一次一小版；drain --ignore-daemonsets；cordon 不搬家
Helm 管套件、Kustomize 管差異；CRD 先於 CR 於 controller

# 除錯（0018–0019）：
get → describe → logs(→--previous) → exec
Exit 137 = OOM；CrashLoop 看 --previous；Pending 看 Events
Service 不通：DNS→endpoints→READY→NetworkPolicy 四站檢查
考場小抄（最後一張）

① 時間是最大敵人：先易後難、不纏鬥、題目要求「apply」就 apply、「看狀態」就別多做。② 指令忘參數：kubectl create ... --help 與 kubectl explain pod.spec.containers 是合法的官方查詢。③ 每題做完全用題目給的驗證方式確認一次（get／describe／logs）。④ 別動 kube-system 的既有元件，除非題目明說。⑤ 作答都在題目指定的 namespace 裡，別開新 namespace 亂放。
