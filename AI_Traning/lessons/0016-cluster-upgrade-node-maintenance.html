叢集升級與節點維護（Killercoda）

0015 把叢集建起來，本課讓它「長大＋保養」：用 kubeadm upgrade 把小版號推上去，再用 cordon／drain／uncordon 讓節點可以安心下線維護。升級是 CKA 的高頻實作題——順序、指令、旗標都要熟。練習一樣在 Killercoda 拋棄式 VM 上進行。

開場：先準備一個「待升級」的叢集

沿用 0015 的 Killercoda 場景（若 VM 已重置、要照 0015 重建：先 apt-cache madison kubeadm 查版本，再 sudo apt-get install -y kubeadm=1.34.x-1.1 kubelet=1.34.x-1.1 kubectl=1.34.x-1.1 把三件套釘在 1.34 後才 init——直接 init 會拿到 repo 最新版，就沒得升了）。本課假設有一台 control-plane 與一台 worker、Kubernetes 1.34.x，要升到 1.35.x。

升級的核心規則

  • 一次只升一個小版號（1.34 → 1.35），不能跳版（1.33 → 1.35 不行）。
  • 先 control plane、後 worker；同一個 control-plane 群也要逐台。
  • 每台節點內部順序固定：先升 kubeadm、再套用（upgrade apply/node）、最後升 kubelet＋kubectl 並重啟 kubelet。
  • kubeadm 升級時預設會自動 renew 憑證（也可以用 --certificate-renewal=false 關掉）。

升級工具分三層，別搞混：kubeadm 管「控制平面靜態元件與設定」，kubelet 是每台節點的執行者，kubectl 是客戶端——三者的版本各自獨立升級。

節點維護三指令

指令做什麼Pod 會怎樣
cordon 把節點標成不可排程（SchedulingDisabled） 不再排新 Pod；已在跑的不動
drain cordon + 把上面的 Pod 驅離（evict）到別的節點 可驅離的 Pod 被安全搬家；DaemonSet 的例外
uncordon 解除不可排程標記，讓節點恢復收 Pod 之後新 Pod 又能排進來

實作 A：升級 control plane

在 control-plane 上：先把 kubeadm 換到目標版本
# 1. Ubuntu 套件管理：kubeadm/kubelet/kubectl 通常被 apt-mark hold 鎖住，先解鎖
sudo apt-mark unhold kubeadm kubelet kubectl

# 2. 查倉庫裡有哪些可用版本（記下 1.35.x 的正確 x，下面帶入）
apt-cache madison kubeadm | head -n 10

# 3. 升級 kubeadm（把 1.35.x 換成你查到的版號）
sudo apt-get update
sudo apt-get install -y kubeadm=1.35.x-1.1
kubeadm version
升級前檢查 + 套用
# 4. upgrade plan：列出可升級路徑與版本差異（先看再動手）
sudo kubeadm upgrade plan

# 5. 在「第一台」control-plane 套用升級（只在一台 cp 跑 apply）
sudo kubeadm upgrade apply v1.35.x
#    它會依序更新 kube-apiserver／controller-manager／scheduler 的 static manifest，
#    完成時印出 "Upgrade complete!"
升級 kubelet 與 kubectl，重啟 kubelet
# 6. kubeadm 只管控制平面 manifest；節點上的 kubelet 要自己換
sudo apt-get install -y kubelet=1.35.x-1.1 kubectl=1.35.x-1.1
sudo systemctl daemon-reload
sudo systemctl restart kubelet

# 7. 把版本鎖回去（防止下次 apt 自動動它）
sudo apt-mark hold kubeadm kubelet kubectl

# 8. 驗收：control-plane 節點 VERSION 顯示 1.35.x
kubectl get nodes
不熟的坑：apt 版號要帶後綴

Debian/Ubuntu 的套件版號是 1.35.x-1.1（後面多一段 Debian revision）。apt-cache madison kubeadm 印出來的那串就是正確寫法——直接複製貼上，別自己臆測。一次只升一個小版，也別把 upgrade apply 的目標寫成「最新」——考試題目會指定精確版號。

實作 B：worker 升級（drain → 升 → uncordon）

在 control-plane 上：先請 worker 把 Pod 交出來
# 9. drain：cordon（不再排新的）+ 把既有 Pod 安全驅離
#    <worker-node> = 你的 worker 節點名（先 get nodes 確認，Killercoda 常叫 node01）
#    --ignore-daemonsets：DaemonSet 的 Pod 不驅離（它們本來就不該被搬走）
kubectl get nodes
kubectl drain <worker-node> --ignore-daemonsets
#    輸出列出被 evict 的 Pod；結束時節點標成 Ready,SchedulingDisabled
在 worker 上：升 kubeadm → node → kubelet
# 10. worker 端的 kubeadm 升級（不必 upgrade apply——那是 cp 的事）
sudo apt-mark unhold kubeadm kubelet kubectl
sudo apt-get update
sudo apt-get install -y kubeadm=1.35.x-1.1

# 11. kubeadm upgrade node：更新 worker 上的 kubelet 設定
sudo kubeadm upgrade node

# 12. 換 kubelet/kubectl 並重啟 kubelet
sudo apt-get install -y kubelet=1.35.x-1.1 kubectl=1.35.x-1.1
sudo systemctl daemon-reload
sudo systemctl restart kubelet
sudo apt-mark hold kubeadm kubelet kubectl
回 control-plane：uncordon 放行
# 13. 解除不可排程，讓 worker 恢復收 Pod
kubectl uncordon <worker-node>
kubectl get nodes
#    兩台都顯示 1.35.x，worker 的 STATUS 不再有 SchedulingDisabled

# 14. 驗收：佈 3 顆 Pod 確認 worker 又能正常承接
kubectl create deployment post-upgrade --image=nginx:1.25 --replicas=3
kubectl get pods -o wide
kubectl delete deployment post-upgrade
你該觀察到什麼

第 9–13 步是節點維護的完整節奏：drain 把 Pod 安全搬走（cordon 只是「不再排新的」）→ 在空下來的節點上升級 → uncordon 讓它重新上工。升級 worker 期間你的服務沒有斷線——因為 Pod 早在別的節點上繼續跑。這就是 drain 存在的意義。

實作 C：憑證檢查與 kubeconfig

憑證到期檢查
# 15. kubeadm 簽的憑證有時效；檢查還有多久到期
sudo kubeadm certs check-expiration
#    表格列出各憑證的 RESIDUAL TIME（例如 apiserver 一年、admin.conf 一年）

# 16. 快到期就手動續約（kubeadm 也會在 upgrade 時自動 renew）
sudo kubeadm certs renew all
sudo kubeadm certs check-expiration
kubeconfig 的角色分工
# 17. /etc/kubernetes 下的 kubeconfig 各自代表一個角色
ls /etc/kubernetes/*.conf
kubectl config view
#    admin.conf   → 叢集管理員（kubectl 用的那份）
#    controller-manager.conf → controller-manager 用自己的身分連 apiserver
#    scheduler.conf          → scheduler 的身分
#    kubelet.conf            → 每台節點 kubelet 的身分
收尾（Killercoda VM 直接關掉即可）
# 18. 本課在拋棄式 VM 進行——練習完畢直接關閉場景，本機叢集不受影響
kubectl get nodes
考場小抄

① 升級口訣：cp 先 node 後、一次一小版；每台內「kubeadm → apply/node → kubelet」。 ② 指令五連：apt install kubeadm=版本 → kubeadm upgrade plan → kubeadm upgrade apply vX.Y.Z（cp）／kubeadm upgrade node（worker）→ apt install kubelet=版本 kubectl=版本 → systemctl restart kubelet。③ drain 必帶 --ignore-daemonsets；卡住時看錯誤訊息決定要不要 --delete-emptydir-data 或 --force（題目有 emptyDir Pod 時）。④ cordon 不搬家、drain 搬家、uncordon 復工。⑤ 憑證：kubeadm certs check-expiration／renew all；upgrade 預設自動 renew。⑥ kubeconfig：admin.conf 是管理員那把，/etc/kubernetes/*.conf 各角色一把。

本課戰果

  • 你用 kubeadm upgrade plan/apply 把 control plane 升一個小版號，並升級 kubelet/kubectl。
  • 你用 drain → 升級 → uncordon 完成 worker 的無痛升級。
  • 你學會 cordon／drain／uncordon 的差別與旗標。
  • 你檢查了憑證到期時間，並認識 /etc/kubernetes 各 kubeconfig 的角色。
